Sanitizers 变化详解

毕昇编译器升级 — LLVM 15.0.4 → 21.1.8 各类 Sanitizer 的演进与新增

⚙

概述

从 LLVM 15 到 21，LLVM 的 Sanitizer 生态系统经历了显著扩展： 3 个全新 Sanitizer 被引入 (Numerical/Realtime/Metadata)，ASan/MSan/UBSan 均有重要功能增强， 此外还引入了 GPU Sanitizer、Sanitizer Special Case List v4/v5 以及覆盖率增强等工具链改进。

📋 阅读建议 如果你正在规划从旧版 LLVM 升级到毕昇编译器 21，建议先浏览"版本演进时间线"了解各版本增量， 再按你所用的 Sanitizer 类型（ASan/MSan/UBSan/新 Sanitizer）查阅具体小节。
T

版本演进时间线

以下按 LLVM 版本列出 Clang 文档中 Sanitizers 章节记录的关键变化。

LLVM 16 16.0.0 ASan / MSan
  • -fsanitize-memory-param-retval 默认启用 — 使用 -fsanitize=memory 时，传入函数的未初始化变量和返回的未初始化变量会得到更激进的检测。 可通过 -fno-sanitize-memory-param-retval 恢复旧行为。
  • ASan: 栈使用后返回 (stack-use-after-return) 的检测精度持续改进。
  • UBSan: 持续的边界检查改进。
LLVM 17 17.0.0 平台 / ASan / MSan
  • 多个 Sanitizer 移植到 LoongArch 架构: MSan, DFsan, Profile, XRay 和 libFuzzer。
  • ASan: use-after-scope 检测精度提升，减少误报。
  • MSan: 新增 use-after-destroy 检测能力。
LLVM 18 18.1.0 新 Sanitizer
  • Numerical Sanitizer (NSan) 引入 — 检测浮点运算中的精度问题和异常值（NaN/Inf）。
  • ASan: 支持自定义 operator new[] 的数组 cookie 投毒 (array cookie poisoning)。
  • MSan: use-after-destroy 检测从 HWASan 扩展到 MSan。
  • HWASan 默认启用 use-after-scope 检测。
LLVM 19 19.1.0 新 Sanitizer
  • Realtime Sanitizer (RTSan) 引入 — 检测实时上下文中不安全的系统调用。
  • ASan: 引入稳定 ABI 选项 -fsanitize-stable-abi。
  • UBSan: 持续的溢出检测改进。
LLVM 20 20.1.0 新 Sanitizer
  • Realtime Sanitizer 正式可用 — 通过 -fsanitize=realtime 激活。 检测 [[clang::nonblocking]] 函数中调用的不安全系统库函数（如内存分配和互斥锁操作）。
  • Metadata Sanitizer 引入 — 通过 -fexperimental-sanitize-metadata= 激活。
  • GPU Sanitizer — -fgpu-sanitize 用于 GPU 内核代码。
  • UBSan: 增强聚集类型的 null/alignment 检查 (#164548)。
  • 覆盖率: -fsanitize-coverage-stack-depth-callback-min= 选项引入，支持设置栈深度回调的最小阈值。
LLVM 21 21.1.8 工具链
  • Sanitizer Special Case List (SSCL) v4/v5 — 引入格式版本 4（过渡期，兼容旧路径匹配但发出警告）和版本 5（完全规范化路径匹配，去除 ./ 前缀）。 Windows 上路径分隔符变为斜杠无关（/ 和 \ 互相匹配）。
  • UBSan: 新增 __ubsan_default_suppressions 支持，允许程序在编译时指定默认抑制规则。
  • TSan: 新增随机延迟功能，帮助发现稀有的线程交错。
A

ASan (AddressSanitizer) 变化

AddressSanitizer 在多个版本中获得持续改进，覆盖栈、堆、全局变量的更多类别内存错误。

Stack-use-after-return (LLVM 16+)

栈使用后返回检测精度持续改进。LLVM 16 开始对函数返回后的栈变量访问有更准确的检测。

示例: 启用栈返回检测
# 默认模式 - 栈返回检测已启用
clang -fsanitize=address -fno-omit-frame-pointer program.c

# 显式控制栈返回检测模式
# ASAN_OPTIONS=detect_stack_use_after_return=1

Use-after-scope 检测 (LLVM 17+)

作用域后使用检测精度大幅提升。LLVM 17 开始更准确地追踪变量离开作用域后的访问，减少误报。

示例: 启用 scope 检测
clang -fsanitize=address -fsanitize-address-use-after-scope program.c

Array Cookie 投毒 (LLVM 18+)

支持自定义 operator new[] 的数组 cookie 投毒。当使用带数组 cookie 的 new[] 分配时，ASan 会正确标记 cookie 区域，检测越界访问。此修复解决了 PR19838 — 含数组 cookie 的 new[] 分配左越界访问未被检测到的问题。

示例: 数组越界检测
// 编译时 ASan 自动处理 array cookie
clang++ -fsanitize=address -O1 -g test.cpp

// 运行时默认自动检测 (LLVM 18+)
// 无需额外选项，与普通 ASan 使用方式一致

稳定 ABI 选项 (LLVM 19+)

引入 -fsanitize-stable-abi 选项，提供跨版本的稳定 ABI 接口，使得使用 ASan 编译的库可以在不同 minor 版本的 LLVM 运行时之间兼容工作。

示例: 启用稳定 ABI
# 编译时启用稳定 ABI 模式
clang -fsanitize=address -fsanitize-stable-abi program.c

# 适用于需要跨版本兼容共享库的场景
M

MSan (MemorySanitizer) 变化

MemorySanitizer 检测未初始化内存的读取。在 LLVM 15 到 21 期间主要增强了函数边界检测能力。

-fsanitize-memory-param-retval 默认启用 (LLVM 16)

这是 MSan 在 LLVM 15→21 期间最重要的行为变化。 使用 -fsanitize=memory 时，传入函数的未初始化参数和函数返回的未初始化值会得到更激进的检测。 如果旧代码依赖旧行为，需要使用 -fno-sanitize-memory-param-retval 恢复。

示例: 对比新旧行为
# LLVM 15 (旧行为): param-retval 默认关闭
clang -fsanitize=memory program.c

# LLVM 16+ (新行为): param-retval 默认启用
# 更积极地检测函数边界的未初始化内存
clang -fsanitize=memory program.c

# 恢复旧行为
clang -fsanitize=memory -fno-sanitize-memory-param-retval program.c

Use-after-destroy 检测 (LLVM 17+/18+)

LLVM 17 起 MSan 新增了对 use-after-destroy 的检测能力。LLVM 18 进一步在 HWASan 中将 use-after-scope 设为默认开启。

示例: 启用 use-after-destroy
# 启用 MSan + use-after-destroy
clang -fsanitize=memory -fsanitize-memory-use-after-dtor program.c
⚠ 迁移注意 LLVM 16 的 MSan 行为变更 (-fsanitize-memory-param-retval 默认开启) 可能导致 升级后出现大量新的未初始化内存报告。请在升级前在测试环境中使用 CI 验证， 确认报告为真实缺陷后修复，或使用 -fno-sanitize-memory-param-retval 作为临时缓解措施。
U

UBSan (UndefinedBehaviorSanitizer) 变化

UBSan 在多个版本中获得持续改进，从边界检查到聚集类型的对齐检测。

持续改进 (LLVM 16+)

LLVM 16 起 UBSan 获得了持续的边界检查改进，包括更精确的有符号整数溢出检测、移位操作检测和类型转换检查。

聚集类型的 Null/Alignment 检查 (LLVM 20+)

UBSan 现在可以检测聚集类型（struct/class 对象）成员的 null 指针解引用和对齐违规。此前这些检查仅适用于基本类型。

示例: 聚集类型对齐检查
# UBSan 现在对 struct 成员也进行 null/alignment 检查
clang -fsanitize=undefined -O1 -g program.c

__ubsan_default_suppressions (LLVM 21+)

新增 __ubsan_default_suppressions 支持。用户可以在程序中定义一个返回抑制规则字符串的函数，允许在编译时指定默认的 UBSan 抑制规则，无需依赖外部抑制文件。

示例: 编译时抑制规则
// 在源代码中定义默认抑制规则
const char *__ubsan_default_suppressions() {
  return "vptr_check:somelib.so\n"
         "function:specific_func\n";
}
N

全新 Sanitizer 类型

LLVM 15 到 21 期间引入了 3 个全新的 Sanitizer，涵盖数值精度、实时安全和元数据领域。

Numerical Sanitizer (NSan) — LLVM 18+

检测浮点运算中的精度问题、异常值（NaN/Inf）和数值稳定性问题。适用于科学计算和金融应用中对数值精度要求极高的场景。通过 -fsanitize=numerical 启用。

示例: 启用数值检测
clang -fsanitize=numerical -g math_heavy.c

Realtime Sanitizer (RTSan) — LLVM 19+/20+

检测实时上下文中不安全的系统库调用（如内存分配 malloc、互斥锁 pthread_mutex_lock 等）。适用于音频处理、游戏引擎、嵌入式实时系统等场景。由 -fsanitize=realtime 激活。标记为 [[clang::nonblocking]] 的函数中调用不安全系统函数时会报错并退出。

示例: 启用实时检测
// 编译时启用 RTSan
clang -fsanitize=realtime audio_callback.c

// 标记实时函数
[[clang::nonblocking]]
void audio_callback(float *buffer) {
  // RTSan 会检测: malloc, free, pthread_mutex_lock 等
  process_audio(buffer);
}

Metadata Sanitizer — LLVM 20+

通过 -fexperimental-sanitize-metadata= 激活，将元数据附加到 IR 级别，支持自定义分析工具。当前为实验性特性，适用于研究用途和定制化分析。

示例: 启用元数据
# 实验性元数据 Sanitizer
clang -fexperimental-sanitize-metadata=all program.c

GPU Sanitizer — LLVM 20+

通过 -fgpu-sanitize 对 GPU 内核代码启用 Sanitizer 检测。适用于 CUDA/HIP/OpenMP 等 GPU 编程模型，帮助检测 GPU 设备代码中的内存错误和数据竞争。

示例: GPU Sanitizer
clang -fgpu-sanitize -x cuda kernel.cu
I

Sanitizer 集成与工具链改进

Sanitizer Special Case List (SSCL) v4/v5 (LLVM 21+)

Sanitizer 特殊清单 (-fsanitize-ignorelist) 和警告抑制映射 (--warning-suppression-mappings) 现在支持格式版本 4 和版本 5（由 #!special-case-list-v4 指示）。

  • 版本 4: 过渡期，同时匹配规范化和非规范化路径（对旧匹配发出警告）。
  • 版本 5: 完全要求规范化路径匹配（去除 ./ 前缀）。
  • Windows: 路径分隔符变为斜杠无关 — / 和 \ 互相匹配。
示例: SSCL v4/v5 格式
# Version 4 (过渡格式) — 兼容旧路径
#!special-case-list-v4
# 旧格式 ./src/file.cpp 仍然匹配但发出警告
src:src/file.cpp

# Version 5 (新格式) — 规范化路径
#!special-case-list-v5
# 路径必须不含 ./ 前缀
src:src/file.cpp

覆盖率增强 (LLVM 20+)

新增 -fsanitize-coverage-stack-depth-callback-min=<N> 选项。 设置栈深度回调的最小阈值，仅当函数调用栈深度超过 N 时才触发覆盖率回调，减少冗余的覆盖率数据。

示例: 栈深度阈值
# 仅栈深度 >= 8 时触发覆盖率回调
clang -fsanitize-coverage=trace-pc-guard \
      -fsanitize-coverage-stack-depth \
      -fsanitize-coverage-stack-depth-callback-min=8 \
      program.c

TSan 随机延迟 (LLVM 21+)

ThreadSanitizer 新增随机延迟功能，在线程调度中引入随机延迟，帮助发现稀有的线程交错和竞争条件。

⚠

迁移注意事项

从 LLVM 15 升级到 21 时，以下 Sanitizer 行为变化需要特别关注。

变更项 影响版本 影响描述 建议操作
-fsanitize-memory-param-retval 默认启用 LLVM 16 使用 MSan 时产生大量新的未初始化内存报告 验证报告真实性后修复；或使用 -fno-sanitize-memory-param-retval 回退
HWASan use-after-scope 默认启用 LLVM 18 HWASan 用户将默认获得 use-after-scope 检测 通常无负面影响；如遇误报可回退
SSCL v4 路径匹配行为变更 LLVM 21 ./ 前缀路径匹配将发出警告（v4），未来版本将完全移除 更新 ignorelist 文件中的路径，移除 ./ 前缀
新 Sanitizer 可用 LLVM 18-20 NSan/RTSan/Metadata Sanitizer 可选择性启用 评估是否需要引入到 CI 流水线中
💡 升级策略建议 建议分阶段升级：先使用与 LLVM 15 兼容的 Sanitizer 选项在 LLVM 21 上构建并运行测试， 确认无新增误报后，再逐步启用新版本特有的检测能力（如 NSan、RTSan 等）。
S

总结

Sanitizer LLVM 15 状态 LLVM 21 状态 关键变化
ASan 基础地址检测 增强的栈/heap/全局变量检测 Stack-use-after-return, use-after-scope, array cookie, 稳定 ABI
MSan 基础未初始化内存检测 增强的函数边界检测 param-retval 默认启用, use-after-destroy
UBSan 基础未定义行为检测 增强的类型对齐检查 聚集类型 null/alignment 检查, __ubsan_default_suppressions
TSan 标准数据竞争检测 增强的线程交错检测 随机延迟功能 (LLVM 21)
NSan 不存在 新增 (LLVM 18+) 浮点精度与异常值检测
RTSan 不存在 新增 (LLVM 19+/20+) 实时上下文安全检测
Metadata Sanitizer 不存在 实验性 (LLVM 20+) IR 级别元数据附加
GPU Sanitizer 不存在 新增 (LLVM 20+) GPU 内核代码检测
