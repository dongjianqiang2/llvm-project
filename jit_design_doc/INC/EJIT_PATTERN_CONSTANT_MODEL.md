# 嵌值安全模型：哪些 period 数组访问可以被常量化

> 草稿 v0.1（2026-08-19，待讨论）。本文自包含，从一维场景讲起，术语集中在文末定义。
> 前置：已了解 EJIT 的基本标记（`ejit_dim` / `ejit_period_arr`）与 JIT 特化概念。

## 0. 要解决的问题（一句话）

JIT 编译某个特化版本时，编译器把 period 数组的访问**嵌成常量**（编译期读内存、写死进代码）。问题：**哪些访问可以嵌，哪些不能？** 判断必须在**编译前的源码形态**上做——因为编译后形态信息就丢了。

## 1. 基本模型（三个概念）

**特化版本**：按 dim 取值编译出来的代码。`f(cell)` 在 cell=0 时编译出 f_0，cell=1 时编译出 f_1。

**实例与生命周期**：period 数组的每个格子是一个"实例"。每个实例有自己的生命周期：激活 → 失效 → 可以**再次激活**。数据在激活时写入，**再次激活时可能重写**（写的是新数据）。谁管实例的生命周期？`ejit_activate/deactivate` 之类的接口，按实例切换。

**版本复核**：每次调用特化版本（如 f_0）时，运行时检查"和这次调用相关的实例"的版本号。实例再次激活 → 版本号提升 → 版本复核发现变化 → **f_0 作废，重新编译**。这样 f_0 里嵌的值一定是"当前有效的数据"。

到这里有一个关键事实，它是全文的地基：

> **版本复核只覆盖"本次调用的 dim 取值对应的实例"。** f_0 的复核只查 cell=0 那个实例（以及函数里其他 dim 对应的实例）。复核不查别的实例。

## 2. 一维的例子：问题是怎么产生的

```c
f(dim cell) {
  use(g[cell]);     // 访问实例 (0)
  use(g[cell + 1]); // 访问实例 (1) —— 注意这个
}
```

cell=0 编译出 f_0。编译器把两处访问都嵌成常量：

- `g[cell]` → 嵌的是实例 **(0)** 的数据。实例 (0) 再次激活、数据重写 → 版本号提升 → f_0 复核时发现 → 重新编译 ✓ 安全。
- `g[cell+1]` → 嵌的是实例 **(1)** 的数据。但是——f_0 的复核只查实例 (0)，**不查实例 (1)**。实例 (1) 再次激活、数据重写 → 版本号提升发生在 (1) 上 → f_0 完全不知道 → 继续用旧值 ✗ **错误**。

一句话：**f_0 事实上依赖实例 (1) 的生命周期，但这层依赖没有被记录、没有被复核。** 数据重写后，f_0 里 `g[cell+1]` 嵌的还是旧值。

### 为什么编译期拦不住

参数替换之后，`g[cell]` 变成 `g[0]`，`g[cell+1]` 变成 `g[1]`——**两个访问在编译产物里一模一样**。负责嵌值的编译步骤只能看到 `g[0]` 和 `g[1]`，看不到"这个 0 是 cell 本身、那个 1 是 cell+1 算出来的"。所以：

> **判断"能不能嵌"必须发生在参数替换之前，在源码形态上做。**

## 3. 规则：唯一的判据

> **允许嵌值的访问，其下标（替换为常量后）必须精确等于"本次调用的 dim 取值元组"**——即每个下标要么是某个 dim 参数**本身**，要么是该 dim 参数的**折叠表达式**（见 §5）。

换成人话：**只有"这个格子的下标恰好就是本函数这次调用时 dim 的值"的访问，才允许嵌值。** 因为版本复核恰好覆盖的就是这些格子——嵌值和复核是同一组格子，数据一变就重编译，永远一致。

| 访问形式（cell=0 编译时） | 下标对应实例 | 复核覆盖？ | 允许嵌值？ |
|---|---|---|---|
| `g[cell]` | (0) | 是（复核查 (0)） | ✓ |
| `g[cell + 1]` | (1) | **否**（复核只查 (0)） | ✗ |
| `g[5]`（写死的字面量） | (5) | 否 | ✗ |
| `g[loop_var]`（循环变量） | 运行期变量 | 否（且替换不了） | ✗ |

不嵌值的访问怎么办？**保持运行期读取**——代码里留着 `g[cell+1]` 的地址计算和读取，每次运行读最新数据。行为永远正确，只是少一次优化。

> 注意"cell 恰好等于 5"的特殊情况：`g[5]` 和 `g[cell]` 在 cell=5 时指向同一个格子。但编译 f_5 时，`g[5]` 的 (5) 在复核范围内、`g[cell]` 的 (5) 也在——两种情况都安全。判定标准始终是"下标是否**由 dim 参数精确推导**"，`g[5]` 是字面量，即使值碰巧相同也不通过判定（保守，避免分析复杂度）。

## 4. 取地址的情况

```c
f(dim cell) {
  p = &g[cell];     // 地址来自合法下标 → 允许
  use(p->field);    // 经指针访问 → 只要 p 的地址可追溯到上面的合法下标，就允许
}
```

同一函数内，指针从合法下标地址出发，经赋值/分支流传，**继续允许**（编译期能追踪）。指针传给别的函数 → **不再允许**（跨函数追踪不做，保守处理）。

## 5. 多维与折叠的扩展

同一规则，只是下标变成元组：

**多维数组**（period = (dim1, dim2)）：
- `g[cell][slot]`：下标元组 (cell, slot) == 本次调用元组 ✓ 允许
- `g[cell][slot+1]`：元组 (cell, slot+1) ≠ ✓ 不允许

**折叠**（period = (cell, slot%10)，即 slot 维折叠）：
- 实例是折叠后的元组 **(cell, slot%10)**；版本复核也按折叠后的元组查
- `g[cell][slot%10]`：下标元组 (cell, slot%10) == 复核元组 ✓ 允许（嵌的值 = 折叠后格子 (cell, k) 的数据）
- `g[cell][slot]`（没有写 %10）：**不能嵌**——slot 原值对应的格子不在复核范围（复核查的是 slot%10 的格子）→ 保持运行期读取 ✓（这正是不要求"自动改写访问"的原因：写 `slot` 就是运行时读，写 `slot%10` 才允许嵌）
- `g[cell][slot%10 + 1]`：偏置了 → 不允许

**展平数组**（一维，下标自己算）：`g[cell*10 + slot%10]`——下标的成分 = cell（dim 本身）和 slot%10（折叠表达式），构成的格子 == 复核元组 ✓ 允许。判定的方法是把下标表达式拆成"成分"，每个成分必须是 dim 本身或它的折叠表达式。

**嵌套结构体**（外层数组 + 成员数组）：`g[cell].member[slot%10]`——两段下标各自判定，都合法就允许。

**一个容易混淆的点**：编译后 `g[cell][slot%10]` 的下标也会变成常量（如 (5, 8)），和 `g[5][8]` 字面量长得一样——但判定在编译前做，`g[cell][slot%10]` 通过、`g[5][8]` 不通过，两者天然区分，不会误判。

## 6. 这个规则是新加的还是现状已有的？

**现状没有这条规则**：现状编译管线对"参数替换后全常量"的访问一律嵌值——`g[cell+1]` 这类访问现状也会被嵌，且无复核跟踪。**只要业务里存在"非精确 dim 下标"的 period 数组访问，现状就有同样的洞。**（可能现状业务没这么写，洞没被触发；也可能触发了没人发现。）

所以这条规则同时是：
1. **新设计**：多维/折叠场景下嵌值资格判定
2. **现状的修复**：补上"下标必须精确等于复核元组"的限制

实现落点：编译期（源码形态）判定 → 给"允许嵌值"的访问打上标记（复用 `ejit_may_const` 机制，兜底恢复路径同步升级为按本规则判定）。

## 7. 待确认

1. 折叠表达式的"精确"范围：`slot%10` 必须与 fold 声明**完全一致**（operand 相同）？还是允许等价形式（如 `slot - slot/10*10`）？——倾向完全一致，等价形式不做识别。
2. 字面量下标 `g[5]`：倾向一律不嵌（保守），即使值碰巧在复核范围内。
3. 跨函数指针传递：本轮不做（§4），列为后续。
4. 现状的洞：是否需要在文档中正式记录为"已知问题"，并加 Sema 警告（非精确 dim 下标的 period 访问提示）？

## 8. 术语对照（本文用到的词，一次性定义）

| 词 | 含义 |
|---|---|
| 特化版本 | 按 dim 取值编译的代码（cell=0 → f_0） |
| 实例 | period 数组的一个格子；生命周期（激活/失效）的粒度 |
| 版本复核 | 调用特化版本时检查相关实例的版本号；实例重新激活 → 版本提升 → 特化作废重编译 |
| dim 取值元组 | 本次调用时各 dim 参数的值（如 (cell, slot)）；复核覆盖的就是这个元组对应的实例 |
| 折叠 | dim 值到实例下标的变换（如 slot → slot%10） |
| 折叠表达式 | 源码里写出来的折叠形式（`slot%10`）；只有这种形式允许嵌值 |
| 嵌值 | 编译期读内存、把 period 数据写死进特化代码 |
| 精确推导 | 下标由 dim 参数本身或它的折叠表达式构成，无任何额外加减 |
