EJIT 构建与部署手册

从开发构建、集成测试到 AArch64、bare-metal、lipo 单对象和 SRE 模式部署。

1. 构建目录和用途

目录用途典型目标
build_debug_x86/x86 Debug 开发构建，适合调试 clang/opt/lldclang opt lld
build_release_x86/x86 Release，适合 EJIT 测试和静态库链接LLVMEJIT lld
build_debug_aarch64/AArch64 Debug 交叉开发clang opt lld
build_release_aarch64/AArch64 Release runtime / lipo pipelineLLVMEJIT lld

2. 推荐构建命令

# 开发日常：x86 debug
./build.sh debug x86
ninja -C build_debug_x86 clang opt lld

# EJIT 测试：x86 release runtime
./build.sh release x86
ninja -C build_release_x86 LLVMEJIT lld

# AArch64 runtime
./build.sh release aarch64
ninja -C build_release_aarch64 LLVMEJIT lld
机器 CPU/内存有限时，优先使用 targeted ninja 目标，不要随意全量构建。

3. 编译用户程序

用户程序应使用本仓库构建出的 Clang，并链接对应的 EJIT runtime 静态库。

build_release_x86/bin/clang -O2 -g \
  -Illvm/include -Ibuild_release_x86/include \
  app.c \
  build_release_x86/lib/libLLVMEJIT.a \
  -fuse-ld=lld -o app

建议以 ejit_test/build.sh 为准同步实际链接 flags。

4. 集成测试

# 构建并运行全部集成测试
./ejit_test/build.sh --run

# 运行指定测试
./ejit_test/build.sh --run ejit_attr_test ejit_ptr_period_test

# 仅构建
./ejit_test/build.sh ejit_config_api_test
测试类型代表测试覆盖点
属性/metadataejit_attr_test6 个属性、CodeGen metadata
正确性ejit_jit_verify_test常量折叠、死分支消除

多维ejit_multidim_test多 period 数组维度
性能ejit_perf_bench编译时间、cache hit 延迟

6. 后端裁剪

面向嵌入式交付时，开启稳定裁剪选项减少 EJIT runtime 依赖体积。

# CMake 选项
-DEJIT_TRIM_LLVM_BACKEND=ON

裁剪内容包括部分 AArch64 可选特性、GlobalISel、调试/EH/ObjCARC/CFGuard 等路径。

7. lipo 单对象交付

将多个 LLVM archive 抽取、GC、合并为单个 ejit.o，便于 bare-metal 链接。

./ejit_test/lipo/run_aarch64_pipeline.sh \
  build_release_aarch64 \
  ejit_test/lipo/ejit.o

# 使用单对象运行集成测试
./ejit_test/build.sh --run --lipo=ejit_test/lipo/ejit.o

8. Bare-metal 部署

  • 链接脚本必须保留 __ejit_registry_bitcode[]、__ejit_registry_period[] 等 section。
  • 构造函数不可用时，设置 forceStaticRegistry = true。
  • 无 dlsym 时，确保外部符号通过自动或手动 ejit_register_symbol 注册。
  • POSIX/std stubs 只是链接占位；JIT 可执行内存应使用平台 code pool。

9. SRE Code Pool

-DEJIT_SRE_CODE_POOL=ON
-DEJIT_CODE_POOL_4K_SEAL=ON
能力说明
2MiB pool从平台分配 2MiB 对齐代码池
4K seal将写入页拆为 4K 并单独设置执行权限
平台符号需要 enable_ex、split_2m_to_4k、SRE_MemDbgAlloc
限制池生命周期内通常不物理释放代码内存

10. SRE Taskpool

./build.sh release aarch64_be --freestanding --sre-taskpool

Taskpool 用于没有 C++ thread 库的 SRE 异步编译：单 worker、MPSC 队列、去重表、分桶 cache。跨核共享 taskpool 还需要共享内存映射、执行权限和 I/D cache 一致性验证。

SRE taskpool 属于平台相关模式，必须做目标真机验证。
