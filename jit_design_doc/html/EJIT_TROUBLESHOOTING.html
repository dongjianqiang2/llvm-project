EJIT 故障排查手册

按症状定位：JIT 没触发、触发但没优化、运行时 fallback、裸核/SRE 问题。

← 文档索引API 速查架构图
总原则： EJIT 失败不应导致程序崩溃；wrapper 收到 NULL 后必须 fallback 到 AOT 原函数体。排障目标通常是“为什么没走 JIT/为什么没优化”，而不是“程序为什么无法运行”。

1. 快速定位流程

1. 编译期是否识别属性？
   └─ 看 Clang Sema/CodeGen 是否有 EJIT 诊断或 metadata
2. AOT pass 是否生效？
   └─ 看 @__ejit_bitcode、ejit_compile_or_get、jit_dispatch/jit_fallback
3. 运行时是否初始化和注册？
   └─ ejit_init 返回值、last_error、registry/static table
4. 时间窗是否 active？
   └─ ejit_is_active(period, idx)
5. cache 是否命中或编译成功？
   └─ ejit_get_stats hits/misses/entryCount
6. PASS6 是否替换字段 load？
   └─ dumpJITDir 检查优化后 IR

2. 症状：JIT 完全没触发

检查 1：函数是否标了 EJIT_ENTRY

没有 EJIT_ENTRY，AOT pass 不会为该函数嵌入 bitcode 和生成 wrapper。

检查 2：是否用了带 EJIT 的 Clang

使用系统 Clang 可能不认识 EJIT 属性，或者不会运行 EJIT pass。

build_release_x86/bin/clang --version

检查 3：IR/二进制里是否有 wrapper 特征

关键词含义
ejit_compile_or_getwrapper 入口调用运行时
jit_dispatchJIT 成功路径
jit_fallbackAOT fallback 路径
@__ejit_bitcode嵌入 bitcode

检查 4：是否调用 ejit_init

ejit_init 前注册信息未消费，runtime 组件未就绪。

检查 5：时间窗是否激活

ejit_activate("cell", idx);
assert(ejit_is_active("cell", idx));

3. 症状：JIT 触发但一直 fallback

可能原因确认方式处理
异步模式首次调用首次 miss，stats misses 增加但 entryCount 未立即增加多调用一次；或切换 SYNC 验证
时间窗未 activeejit_is_active false / last_error NOT_ACTIVE调用 ejit_activate
bitcode 未注册last_error BITCODE_NOT_FOUND检查 PASS1、registry、section 保留
外部符号缺失JITLink/ORC 符号解析失败自动或手动 ejit_register_symbol
目标后端缺失JIT 编译报 target/backend 错误确认构建包含目标架构
代码内存不足MEMORY/CACHE_FULL/code size 错误调大上限或降低 opt level

4. 症状：JIT 有了但分支没折叠

  1. 字段是否标注 EJIT_PERIOD_CONST？
  2. 字段是否是 volatile？volatile 不替换。
  3. 全局对象是否标注 EJIT_IN_PERIOD(static) 或 EJIT_IN_PERIOD_ARRAY(name)？
  4. 入口参数是否标注同名 EJIT_DIM(name)？
  5. 访问是否是可分析的全局变量/GEP 链？复杂 PHI/select 指针会跳过。
  6. 被调用函数里的 load 是否已经 inline 到入口函数闭包里？
  7. 设置 dumpJITDir，检查 PASS6 后 IR。
ejit_config_t cfg = {0};
cfg.dumpJITDir = "/tmp/ejit-ir";
ejit_init(&cfg);

5. 症状：修改配置后结果不对

通常是旧特化代码没有失效。修改 EJIT_PERIOD_CONST 字段时必须遵守生命周期。

// 推荐：生命周期函数
EJIT_PERIOD_GUARD(cell)
void update_cell(EJIT_DIM(cell) uint8_t idx) {
    g_cellCfg[idx].mode = MODE_SAFE;
}

// 或手动：
ejit_deactivate("cell", idx);
g_cellCfg[idx].mode = MODE_SAFE;
ejit_activate("cell", idx);
不要在未 deactivate 的情况下直接改 active 时间窗内的 may_const 字段。

6. 编译期诊断速查

诊断原因修复
multiple period attributes同一变量被多个 period 标记只保留一个 EJIT_IN_PERIOD 或 EJIT_IN_PERIOD_ARRAY
period cannot be used on array数组用了 EJIT_IN_PERIOD改用 EJIT_IN_PERIOD_ARRAY
period_arr requires array标量用了 EJIT_IN_PERIOD_ARRAY标量静态配置用 EJIT_IN_PERIOD(static)
array too large固定数组超过限制缩小数组或改造数据组织
period_arr_ind must be integer维度参数不是整数使用 uint8_t/int
too many dimensions超过 4 个维度拆分函数或合并业务维度
recursive EJIT_ENTRYJIT 入口递归移除递归或取消 EJIT_ENTRY
lc requires matching index生命周期函数没有同名下标参数添加 EJIT_DIM(name)

7. Bare-metal / SRE 问题

症状重点检查
ejit_init 找不到注册信息linker script 是否保留 __ejit_registry_*[] section；是否开启 forceStaticRegistry
符号解析失败外部函数/全局变量是否自动或手动 ejit_register_symbol
JIT 代码不可执行CodePool 是否调用平台 enable_ex；I/D cache 是否同步
SRE taskpool 不编译worker 是否启动；queue/dedup 是否满；instance 是否 disabled
跨核执行失败共享 section 映射、相同虚拟地址、执行权限、cache coherence、owner 选举
