2. Scenario descriptions

Lifecycle active: sync miss

The period is active and the version is valid, but the Cache Table has no entry for the current cacheKey; the business thread synchronously completes bitcode loading, PASS6, optimization, and JITLink, and after publishing the cache this call runs JIT directly.

Lifecycle active: async miss

The period is active and the version is valid, but the Cache Table misses; the current call only submits an async task and falls back, the worker compiles in the background and publishes to the Cache Table, and later calls with the same cacheKey hit.

Lifecycle active: cache hit

The period is active, the version matches, and the Cache Table already has a valid function pointer for the current cacheKey; the wrapper jumps directly to JIT dispatch without entering the compile flow.

Lifecycle invalid: fallback

When the period is inactive / invalid or a cache entry version is expired, the wrapper cannot use the may_const specialized result; even if an old entry exists in the Cache Table it must safely fall back to the original AOT body.
