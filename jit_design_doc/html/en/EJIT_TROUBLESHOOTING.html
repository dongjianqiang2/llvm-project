EJIT Troubleshooting Guide

Locate problems by symptom: JIT not triggered, triggered but not optimized, runtime fallback, and bare-metal/SRE issues.

← Doc indexAPI referenceArchitecture
General principle: An EJIT failure must never crash the program; when the wrapper gets NULL it must fall back to the original AOT function body. The troubleshooting goal is usually "why didn't it go through JIT / why wasn't it optimized", not "why can't the program run".

1. Quick triage flow

1. Were attributes recognized at compile time?
   └─ Check Clang Sema/CodeGen for EJIT diagnostics or metadata
2. Did the AOT pass take effect?
   └─ Look for @__ejit_bitcode, ejit_compile_or_get, jit_dispatch/jit_fallback
3. Is the runtime initialized and registered?
   └─ ejit_init return value, last_error, registry/static table
4. Is the time window active?
   └─ ejit_is_active(period, idx)
5. Did the cache hit or compile succeed?
   └─ ejit_get_stats hits/misses/entryCount
6. Did PASS6 substitute field loads?
   └─ Inspect the optimized IR in dumpJITDir

2. Symptom: JIT never triggers

Check 1: Is the function marked EJIT_ENTRY

Without EJIT_ENTRY, the AOT pass will not embed bitcode or generate a wrapper for that function.

Check 2: Are you using a Clang with EJIT

A system Clang may not recognize EJIT attributes, or may not run the EJIT passes.

build_release_x86/bin/clang --version

Check 3: Are there wrapper signatures in the IR/binary

KeywordMeaning
ejit_compile_or_getThe wrapper entry calls the runtime
jit_dispatchJIT success path
jit_fallbackAOT fallback path
@__ejit_bitcodeEmbedded bitcode

Check 4: Did you call ejit_init

Before ejit_init, registration info is not consumed and the runtime components are not ready.

Check 5: Is the time window activated

ejit_activate("cell", idx);
assert(ejit_is_active("cell", idx));

4. Symptom: JIT works but branches are not folded

  1. Is the field annotated EJIT_PERIOD_CONST?
  2. Is the field volatile? volatile is not substituted.
  3. Is the global object annotated EJIT_IN_PERIOD(static) or EJIT_IN_PERIOD_ARRAY(name)?
  4. Is the entry parameter annotated with the matching EJIT_DIM(name)?
  5. Is the access an analyzable global variable / GEP chain? Complex PHI/select pointers are skipped.
  6. Has the load in the callee already been inlined into the entry function's closure?
  7. Set dumpJITDir and inspect the IR after PASS6.
ejit_config_t cfg = {0};
cfg.dumpJITDir = "/tmp/ejit-ir";
ejit_init(&cfg);

5. Symptom: Wrong results after modifying config

Usually the old specialized code was not invalidated. When modifying EJIT_PERIOD_CONST fields you must respect the lifecycle.

// recommended: lifecycle function
EJIT_PERIOD_GUARD(cell)
void update_cell(EJIT_DIM(cell) uint8_t idx) {
    g_cellCfg[idx].mode = MODE_SAFE;
}

// or manually:
ejit_deactivate("cell", idx);
g_cellCfg[idx].mode = MODE_SAFE;
ejit_activate("cell", idx);
Do not directly modify a may_const field inside an active time window without deactivating first.
