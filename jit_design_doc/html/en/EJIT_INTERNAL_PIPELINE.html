EJIT Internal Pipeline

For EJIT maintainers: Clang metadata, AOT PASS1~PASS5, runtime PASS6, cache key, registration, and the fallback mechanism.

1. Overall layering

User annotations ↓ Clang Sema / CodeGen ↓ emits !ejit.metadata / !ejit.may_const AOT PASS1: bitcode extraction and embedding AOT PASS2-4: period registration / wrapper / lifecycle AOT PASS5: coordinator ↓ Runtime wrapper calls ejit_compile_or_get ↓ JIT pipeline: param substitution → InstCombine → Inline → PASS6 → L1/L2/L3 → ORC/JITLink ↓ Code Cache / fallback AOT

4. Why PASS1 must run early

!ejit.may_const is load-level soft metadata; standard optimization may merge, delete, or rewrite loads. PASS1 extracts the raw bitcode before optimization and tries to recover metadata via the GV offset list + reAnnotate mechanism.

Correctness principle: losing metadata only means less specialization — it must never cause an incorrect substitution.

5. Wrapper model

void process_cell(uint8_t cellIdx, int value) {
    uint64_t key = ((uint64_t)funcIdx << 32) | cellIdx;
    PFN_process_cell pfn = (PFN_process_cell)ejit_compile_or_get(key, NULL);
    if (pfn)
        return pfn(cellIdx, value);

    // jit_fallback: the original function body continues
    ...
}
  • Single-function hybrid scheme: no separate fallback function is generated.
  • The cache key is computed in registers, avoiding a dims array allocation.
  • Returning NULL means fallback.

7. Runtime JIT Pipeline

  1. ModuleLoader finds the embedded bitcode by funcIndex/cacheKey.
  2. Substitute EJIT_DIM parameters with the current dimension constants.
  3. InstCombine folds zext, GEP, and constant chains.
  4. Inline expands cross-function field accesses.
  5. PASS6 walks loads, recognizing !ejit.may_const or GV offset fallback.
  6. Find the base address + offset from RuntimeState/Registry and read the current memory value.
  7. Replace the load with ConstantInt/ConstantFP.
  8. Run L1/L2/L3 optimization and hand off to ORC/JITLink to produce machine code.
  9. Write to the cache; subsequent wrapper calls hit.

10. Maintainer checkpoints

  • When adding attributes, keep Attr.td, Sema, CodeGen metadata, and lit tests in sync.
  • When changing the wrapper, check debug info, profile, calling convention, varargs, and PHI/return merging.
  • When changing PASS6, follow the "if you cannot prove it, skip it" correctness principle.
  • When changing the cache/taskpool, check invalidation, versioning, concurrent publish, reader release, and memory lifecycle.
  • When changing the bare-metal path, check linker sections, symbol registration, code permissions, and I/D cache.
