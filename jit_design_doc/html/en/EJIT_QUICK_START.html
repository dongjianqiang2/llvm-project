EJIT 5-Minute Quick Start

From zero to a running minimal EmbeddedJIT example.

← Doc indexFull user manualTroubleshooting

0. What you need

  • A Clang built from this repository with EJIT support.
  • Link the EJIT runtime: libLLVMEJIT.a.
  • User code includes llvm/ExecutionEngine/EJIT/EJitRuntime.h.
./build.sh debug x86
./build.sh release x86
ninja -C build_release_x86 LLVMEJIT lld

1. Write a specializable config struct

Mark the fields that stay stable within a time window as EJIT_PERIOD_CONST. Do not mark frequently changing fields.

#include <stdint.h>
#include "llvm/ExecutionEngine/EJIT/EJitRuntime.h"

#define MODE_FAST 1
#define MODE_SAFE 2

struct CellConfig {
    EJIT_PERIOD_CONST uint32_t mode;
    EJIT_PERIOD_CONST uint32_t threshold;
    uint32_t counter;
};

EJIT_IN_PERIOD_ARRAY(cell) struct CellConfig g_cellCfg[16];

2. Annotate the JIT entry function

EJIT_ENTRY marks the original function; EJIT_DIM(cell) tells EJIT which parameter is the cell time-window index.

static void fast_path(int v);
static void safe_path(int v);
static void default_path(int v);

EJIT_ENTRY
void process_cell(EJIT_DIM(cell) uint8_t cellIdx, int value) {
    if (g_cellCfg[cellIdx].mode == MODE_FAST) {
        fast_path(value + g_cellCfg[cellIdx].threshold);
    } else if (g_cellCfg[cellIdx].mode == MODE_SAFE) {
        safe_path(value);
    } else {
        default_path(value);
    }
}

3. Annotate the config-modification function

When modifying an EJIT_PERIOD_CONST field, wrap the lifecycle with EJIT_PERIOD_GUARD. The compiler automatically inserts deactivate/activate.

EJIT_PERIOD_GUARD(cell)
void update_cell_cfg(EJIT_DIM(cell) uint8_t cellIdx,
                     uint32_t mode,
                     uint32_t threshold) {
    g_cellCfg[cellIdx].mode = mode;
    g_cellCfg[cellIdx].threshold = threshold;
}

4. Initialize EJIT and activate the time window

int main(void) {
    ejit_config_t cfg = {0};
    cfg.compileMode = EJIT_COMPILE_SYNC;
    cfg.optLevel = EJIT_OPT_L2;
    cfg.maxCodeMemory = 2 * 1024 * 1024;
    cfg.maxCacheEntries = 4096;
    cfg.enableLogger = true;

    if (ejit_init(&cfg) != EJIT_OK)
        return 1;

    g_cellCfg[3].mode = MODE_FAST;
    g_cellCfg[3].threshold = 10;
    ejit_activate("cell", 3);

    process_cell(3, 100); // first call: compile or fallback
    process_cell(3, 101); // after a cache hit, runs specialized code

    update_cell_cfg(3, MODE_SAFE, 20); // old cache invalidated
    process_cell(3, 102);              // recompile or fallback

    ejit_shutdown();
    return 0;
}

5. Build and run

For real projects, follow the link rules in ejit_test/build.sh. Conceptual commands:

build_release_x86/bin/clang -O2 -g \
  -Illvm/include -Ibuild_release_x86/include \
  quick_start.c \
  build_release_x86/lib/libLLVMEJIT.a \
  -fuse-ld=lld -o quick_start

./quick_start

7. The 5 most common mistakes

  1. Forgetting to call ejit_init.
  2. Forgetting ejit_activate("cell", idx).
  3. Not marking fields with EJIT_PERIOD_CONST.
  4. Not marking the EJIT_ENTRY parameter with EJIT_DIM(cell).
  5. Modifying config fields directly, without EJIT_PERIOD_GUARD or manual deactivate/activate.
If any step fails, EJIT's principle is to return NULL and fall back to AOT — it should never affect program correctness.
