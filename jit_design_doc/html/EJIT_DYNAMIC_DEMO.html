2. 场景说明

同步 miss

miss 后业务线程进入冷路径，完成 bitcode 加载、PASS6、LLVM 优化和 JITLink；发布 cache 后本次调用直接执行 JIT。

异步 miss

业务线程只提交任务并 fallback；worker 后台编译和发布，下一次相同 cacheKey 调用才命中特化代码。

Cache hit

展示成熟热路径：wrapper → period active → cache hit → JIT dispatch，不再经过 LLVM 编译。

失败 fallback

展示 runtime 未就绪、inactive、bitcode 缺失、JITLink 失败等情况都安全回退到 AOT 原函数体。

3. 和真实 EJIT 的对应关系

动画元素对应真实组件关键语义
IR 数据包嵌入 bitcode / cloned LLVM Module冷路径用它重新优化入口函数闭包。
Cache TableEJitCache / taskpool bucket以 funcIdx + dims 为 key 保存特化函数。
Async QueueMPSC queue + dedup table同一 cacheKey 只排一个后台编译任务。
Period 状态RuntimeState active / invalid / version只有 active 且版本有效时才可使用 may_const 特化结果。
Deactivate / Activateejit_period_lc 或手动生命周期 API配置修改会使旧 cache 失效，并触发下一次重新编译。
