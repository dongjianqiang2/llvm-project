EJIT 内部流水线说明

面向 EJIT 维护者：Clang metadata、AOT PASS1~PASS5、运行时 PASS6、cache key、注册和 fallback 机制。

← 文档索引架构图PLAN4

1. 总体分层

用户标注 ↓ Clang Sema / CodeGen ↓ 生成 !ejit.metadata / !ejit.may_const AOT PASS1: bitcode 提取和嵌入 AOT PASS2-4: period 注册 / wrapper / lifecycle AOT PASS5: 协调器 ↓ 运行时 wrapper 调用 ejit_compile_or_get ↓ JIT pipeline: 参数替换 → InstCombine → Inline → PASS6 → L1/L2/L3 → ORC/JITLink ↓ Code Cache / fallback AOT

2. Clang metadata

metadata位置用途
!ejit.metadataFunction标记 EJIT_ENTRY、EJIT_DIM、EJIT_PERIOD_GUARD
!ejit.metadataGlobalVariable标记 EJIT_IN_PERIOD、EJIT_IN_PERIOD_ARRAY、may_const 字段偏移回退信息
!ejit.may_constLoadInstPASS6 主路径识别可替换 load
define void @process(i8 %idx) !ejit.metadata !0 { ... }
!0 = distinct !{!1, !2}
!1 = !{!"EJIT_ENTRY"}
!2 = !{!"EJIT_DIM", !"cell", i32 0}

@g_cellCfg = global [16 x %struct.CellConfig] zeroinitializer, !ejit.metadata !3
!3 = distinct !{!4}
!4 = !{!"EJIT_IN_PERIOD_ARRAY", !"cell", i32 16}

%v = load i32, ptr %field, !ejit.may_const !{}

3. AOT Pass 职责

Pass时机职责关键产物
PASS1 EJitRegisterBitcode标准优化前提取 EJIT_ENTRY 闭包，保留 metadata，嵌入 bitcode，自动注册外部符号@__ejit_bitcode、registry bitcode entries
PASS2 EJitRegisterPeriod非 LTO 优化前 / LTO 优化后扫描 period/static metadata，生成注册调用或静态表period registry entries
PASS3 EJitWrapperGen同上在原函数入口插入 cache key 计算、runtime 调用、dispatch/fallbackjit_dispatch、jit_fallback
PASS4 EJitPeriodHandler同上生命周期函数入口/出口插入 deactivate/activateejit_deactivate、ejit_activate
PASS5 EJitAotModulePass协调按序运行 PASS2-4，快速跳过无 EJIT metadata 模块AOT pipeline 封装

4. PASS1 为什么必须早

!ejit.may_const 是 load 级软 metadata，标准优化可能合并、删除或重写 load。PASS1 在优化前提取原始 bitcode，并通过 GV 偏移列表 + reAnnotate 机制尽量恢复 metadata。

正确性原则：metadata 丢失只会少做特化，不应导致错误替换。

5. Wrapper 模型

void process_cell(uint8_t cellIdx, int value) {
    uint64_t key = ((uint64_t)funcIdx << 32) | cellIdx;
    PFN_process_cell pfn = (PFN_process_cell)ejit_compile_or_get(key, NULL);
    if (pfn)
        return pfn(cellIdx, value);

    // jit_fallback: 原函数体继续执行
    ...
}
  • 单函数混合方案：不生成单独 fallback 函数。
  • cache key 在寄存器中计算，避免 dims 数组分配。
  • 返回 NULL 即 fallback。

6. Cache Key

uint64_t key:
bit 63..32: funcIndex / funcIdx
bit 31..24: dim[3]
bit 23..16: dim[2]
bit 15..8 : dim[1]
bit 7..0  : dim[0]
场景key 低 32 位
仅 static0
单维 cell=30x00000003
二维 cell=1,trp=50x00000501

7. Runtime JIT Pipeline

  1. ModuleLoader 根据 funcIndex/cacheKey 找到嵌入 bitcode。
  2. 替换 EJIT_DIM 参数为当前维度常量。
  3. InstCombine 折叠 zext、GEP 和常量链。
  4. Inline 展开跨函数字段访问。
  5. PASS6 遍历 load，识别 !ejit.may_const 或 GV 偏移回退。
  6. 从 RuntimeState/Registry 找到 base address + offset，读取当前内存值。
  7. 用 ConstantInt/ConstantFP 替换 load。
  8. 运行 L1/L2/L3 优化并交给 ORC/JITLink 生成机器码。
  9. 写入 cache；wrapper 后续命中。

8. PASS6 替换条件

条件说明
必须是 may_const loadload metadata 或 GV 偏移回退命中
根对象可追溯GlobalVariable / 支持的全局指针模式
offset 可计算GEP index 在参数替换和 InstCombine 后为常量
时间窗 activeperiodName + cellIdx 处于 Active
类型可构造 Constant整数、浮点、布尔等受支持类型

PHI/select 指针、未知别名、非 constant offset、null pointer、volatile 字段会安全跳过。

10. 维护者排查点

  • 新增属性时，确认 Attr.td、Sema、CodeGen metadata、lit tests 同步。
  • 改 wrapper 时，检查 debug info、profile、calling convention、varargs、PHI/return 合并。
  • 改 PASS6 时，遵守“无法证明就跳过”的正确性原则。
  • 改 cache/taskpool 时，检查失效、version、并发发布、读者释放和内存生命周期。
  • 改 bare-metal 路径时，检查 linker section、符号注册、代码权限和 I/D cache。
