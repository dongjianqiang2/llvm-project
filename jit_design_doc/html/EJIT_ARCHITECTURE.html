1. 总体架构一览

EmbeddedJIT 将用户源码中的时间窗标注转化为编译期 metadata，并在 AOT 阶段嵌入可供运行时重新优化的 bitcode。运行时根据当前激活的时间窗实例生成特化机器码，并通过 cache 命中直接执行。

编译期 产物/执行 JIT 编译 代码生成/内存

2. AOT 编译期流水线

AOT 编译期分两类 pass：PASS1 必须尽早运行，负责在优化破坏 metadata 之前提取 bitcode；PASS2-4 负责注册、wrapper 和生命周期插桩，由 PASS5 统一协调。

3. 运行时 JIT 与 Cache 架构

运行时入口由 wrapper 调用。热路径只做 cache 查询；冷路径才加载 bitcode、执行优化 pipeline 并生成机器码。

4. 时间窗生命周期状态机

时间窗控制 JIT 特化是否允许使用当前内存值。修改配置前必须使相关实例失效，修改完成后重新激活，后续调用会重新编译或命中新的版本。

5. Bare-metal / SRE 部署架构

在无操作系统或 SRE 环境下，EJIT 需要替代 host 依赖：构造函数注册、动态符号查找、线程库、mmap/mprotect 和 JIT 可执行内存管理。

6. 组件职责速查

层级组件职责用户关注点
Clang 前端Attr.td / SemaEJIT / CGEJIT识别属性、做约束检查、生成 EJIT metadata属性使用是否合法，是否产生诊断
AOT PASS1EJitRegisterBitcode提取 ejit_entry 闭包 bitcode，嵌入二进制，自动注册外部符号是否生成 @__ejit_bitcode
AOT PASS2EJitRegisterPeriod注册 period arrays / static varsejit_activate 能否找到时间窗
AOT PASS3EJitWrapperGen在原函数入口插入 JIT 查询和 dispatch/fallback是否调用原函数名即可触发 JIT
AOT PASS4EJitPeriodHandler为生命周期函数自动插入 deactivate/activate配置修改是否自动失效旧 cache
运行时状态EJitRuntimeState / Registry维护注册信息、active 状态、dense slot初始化、生命周期和裸核注册
运行时缓存EJitCache / Taskpool cache按 funcIdx+dims 查找/发布特化函数命中率、失效、内存上限
