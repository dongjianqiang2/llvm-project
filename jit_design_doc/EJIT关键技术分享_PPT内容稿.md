## 第 1 页：范式 — 时间窗常量 + 运行时特化

**主标题**：EJIT 核心范式：时间窗常量 + 运行时特化
**副标题**：把 AOT 不敢假设的常量，在时间窗内安全地变成编译期事实

### 左栏卡片 1：问题

| 引导词 | 说明 |
|---|---|
| 数据实际不变 | 嵌入式业务大量数据在特定阶段是常量：配置表、模式参数、维度信息 |
| AOT 无法利用 | 静态编译只能保守处理：每次 load、每次判分支，优化机会全部流失 |
| 传统 JIT 不可行 | 嵌入式无 OS / 无文件系统，RAM 100KB–2MB，无法部署完整编译器 |

### 左栏卡片 2：范式

| 引导词 | 说明 |
|---|---|
| 用户声明 | `ejit_period_const`(字段) · `ejit_group`(数据组) · `ejit_dim`(维度) · `ejit_entry`(可特化函数) |
| 运行时协议 | `ejit_activate` 开窗 → 窗口内数据视为编译期常量 → `ejit_deactivate` 关窗 → 版本失效回到 AOT |
| 特化手段 | JIT 编译期从进程内存读实际值，标记 load 替换为常量 → 常量传播 / 分支折叠 / 死代码消除 |

### 右栏：效果示意（代码前后对比，纵向两块）

```
── AOT：每次调用都要 load + 判分支 ──────────────
if (cfg->mode == 7) { 热路径; }     // mode 每次从内存读
else               { 冷路径; }

── 窗口内 JIT：mode==7 已知，冷分支整体消失 ────
热路径;        // load 已替换为常量 7，分支折叠 + DCE
```

### 口述要点

- 一句话定位：**数据在时间窗内是常量，就让它成为编译期常量**。
- 安全性：period_const 是软标注，JIT 失败 / 窗口外永远回退 AOT，语义不变。
- 用户体验：源码加注解、调用原函数名，零其他改动。

## 第 2 页：端到端架构

**主标题**：EJIT 端到端架构：从源码标注到运行时特化
**副标题**：Clang 属性 → 两阶段 AOT → 运行时特化引擎 → 异步调度 · 29 个技术点 / 28 个已实现

### 主体：分层架构图（自上而下，复用 9 月 PPT 第 1 页版式）

```
┌ 源码层 ────────────────────────────────────────────┐
│ Clang 8 个属性标注 (ejit_group / period_const / dim / │
│ entry / free_dim / bound_ptr …) —— 用户唯一接触面    │
└──────────────────── ▼ ─────────────────────────────┘
┌ AOT 编译期（两阶段）───────────────────────────────┐
│ O2/O3 前: bitcode 提取 + 闭包瘦身 + 外链化           │
│           period_const 元数据双重保留 + 预优化           │
│ O2/O3 后: wrapper 插桩 + period 注册                 │
│           生命周期护栏 + 双轨注册                     │
│ 产物: @__ejit_bitcode 嵌入 + 弱符号表                │
└──────────────────── ▼ ─────────────────────────────┘
┌ 运行时特化引擎 ────────────────────────────────────┐
│ 调用 → wrapper 哨兵探测 → 命中直跳 / miss 入队 /     │
│ 失败 fallback AOT                                    │
│ ★ PASS6: 编译期从进程内存读实际值，标记字段 load     │
│   替换为 LLVM 常量（特化收益的主要来源）              │
│ 优化管线: 参数替换 → InstCombine → Inline → PASS6    │
│           → L1/L2/L3 → OrcJIT (LLJIT + JITLink)     │
│ 内存: 4K 页粒度 W^X 封固代码池                       │
└──────────────────── ▼ ─────────────────────────────┘
┌ 异步调度 + 在线 PGO（当前重点，引出后两页）──────────┐
└─────────────────────────────────────────────────────┘
```

### 右侧/底部：三个关键设计决策（小卡）

| 决策 | 内容 |
|---|---|
| 单函数 wrapper | 逻辑插在原函数入口，无独立 wrapper 函数 —— 省一次跳转、无符号膨胀 |
| 元数据驱动 | `!ejit.period_const` 软标注：任何 pass 丢弃它只损失优化机会，不损正确性 |
| 双轨注册 | AOT 版与 JIT 版同一注册表管理，fallback 零成本切换 |

### 口述要点

- 完成度先亮出来：29 个技术点 28 个已实现并接入，唯一待办是真机性能实测。
- 强调"软标注 + fallback"贯穿全链路：每一层失败都退化为普通 AOT 行为。

## 第 3 页：异步编译调度 Taskpool

**主标题**：异步编译调度：裸核上的纯异步单 Worker
**副标题**：无 C++ 线程库 · 无锁并发 · 跨核共享 —— SRE aarch64_be 裸核场景

> 本页详细版式（泳道闭环流程图）直接用《EJIT异步编译_PPT内容稿.md》第一页，此处为浓缩内容。

### 左栏卡片 1：问题

| 引导词 | 说明 |
|---|---|
| 同步阻塞 | miss 时调用方全程等待 bitcode→特化→编译，空闲核无法参与 |
| 无去重 | 多核并发请求同一函数，各自重复编译浪费 CPU |
| 裸核约束 | 无 thread/mutex/atomic 库，只有原子变量 + 栅栏 + 平台 task 原语 |

### 左栏卡片 2：关键技术

| 引导词 | 说明 |
|---|---|
| 纯异步模型 | producer 入队即返回 fallback；单 worker 跑在 EJitSreTask 平台 task |
| 无锁 MPSC | Vyukov 环形队列 1024 槽，多 producer CAS 抢槽 |
| Dedup 去重 | funcIndex 数组下标 CAS 占位 O(1)；冲突/队满自动回滚 + fallback |
| 分桶缓存 | 32 桶各自独立 RwLock：读 tryRead 不等待，写 spin 等读者退场 |
| Version 懒失效 | toggle → version 单调递增；worker 双检查点挡竞态 |
| 跨核共享 | POD 共享 blob + CAS owner 选举，生产 preset 钉核 6；4K 页粒度跨核 seal (v5 ABI) |

### 右栏：数据流闭环（顺时针环形）

```
业务核 Core 0..N          跨核共享状态 EJIT_SHARED_SECTION      Worker 核
─────────────────         ────────────────────────────         ─────────
① compile_or_get    miss→  TaskQueue (MPSC+Dedup)   →  ④ pollOne 出队
② tryRead 缓存查询   ←──   结果缓存 32 桶  ←──────────  ⑤ 检查点1 (version)
③ 命中 → 直跳执行 ←publish│ SwitchController (version) ←──  ⑥ JIT 编译
                                                          ⑦ 检查点2 → publish
```

### 左栏卡片 3：进展

| 状态 | 内容 |
|---|---|
| ✓ | 单 worker 纯异步调度 + C ABI (compile_or_get / release_read / stats) |
| ✓ | 跨核共享单 worker：POD 共享 blob + CAS owner 选举 |
| ✓ | host 测试 TaskPool 91/91 · SharedTaskPool 158/158（注入式核 ID，无真实线程） |
| △ | 待真机：跨核 I/D-cache 一致性 · 真 join · worker 栈峰值实测 |

### 口述要点

- 约束本身就是亮点：在"没有 C++ 线程库"的裸核上重建了一整套并发调度。
- 单 consumer 是无锁正确性的硬约束，也是刻意选型：一个 worker 编译吞吐足够，换来整个队列的免锁简化。
- 命中侧配套：多版本 inline cache（frame-less 探测直跳）+ 跨核共享 cell 表（drain 原地清零失效）。

## 第 4 页：在线 PGO + Value Profiling

**主标题**：在线 PGO：从"常量感知"到"频度感知"
**副标题**：Tier-1 采样 → 内存合成 profile → Tier-2 重编译 · 无文件系统 · 无 deopt

### 左栏卡片 1：动机

| 引导词 | 说明 |
|---|---|
| 值已知 ≠ 频度已知 | 常量特化解决"值已知"，但分支热度/块频度 JIT 管线不感知，仍按静态启发式布局 |
| 传统 PGO 不可行 | profile 落盘 + 离线重编译依赖文件系统 —— 嵌入式没有 |
| 无 deopt 可用 | 不像 Java/JS JIT 可以去优化回退，EJIT 推测必须一次正确 |

### 左栏卡片 2：机制

| 引导词 | 说明 |
|---|---|
| Tier-1 采样 | 插桩版特化代码累计边/块执行频度，64 样本窗口 |
| 内存合成 | 直接在内存合成 indexed profile —— 零文件、零 malloc |
| Tier-2 重编译 | 真实 profile 写 `!prof` → 分支概率 + MachineBlockPlacement 热路径布局 |
| Value Profiling | 三类 value site：间接调用目标 / 动态 memop 大小 / 循环边界；每核 K-way heavy-hitter 双缓冲 |
| 带 guard 推测 | 生成"带护栏的热路径 + 语义一致的通用 fallback"，绝不无条件推测（默认关闭，宏开启） |

### 右栏：两级编译数据流（纵向）

```
调用 ──→ Tier-1 插桩特化代码（累计边/块频度）
              │ 64 样本窗口
              ▼
        内存合成 indexed profile
              │ admission 并发控制 + 采样 CAS 封顶
              ▼
         Tier-2 重编译（PGOUse !prof）
              │
              ▼
        热路径布局优化后的特化代码
```

### 左栏卡片 3：实测校准结论（诚实工程）

| 状态 | 内容 |
|---|---|
| ✓ | Tier-1/Tier-2 全链路生产可用（v0.12 修复 ORC 符号 claim 阻塞后） |
| ✓ | admission 并发控制 + 采样 CAS 封顶（共享 ABI v10） |
| ✓ | 校准结论：真实闭包上 PGO 内联阶段是 no-op —— AOT 预内联已消灭全部 callee |
| ✓ | 实际价值集中在后端 MachineBlockPlacement 热路径块布局 |
| △ | 收益数字待真机实测 |

### 口述要点

- 主线递进：第 1 页解决"值已知"，本页解决"频度已知"。
- 重点讲校准结论：只有拿真实闭包跑过才知道 PGO 内联是 no-op、价值在块布局 —— **我们做的是测量，不是信仰**。
- 无 deopt 约束下的推测设计（guard + fallback）体现嵌入式 JIT 与服务器 JIT 的本质差异。
