EmbeddedJIT 架构汇报图

① AOT 编译期：从源码到可特化 Bitcode

Clang 源码属性与 IR Metadata

  • ejit_entry 标识 JIT 优化入口函数。
  • ejit_may_const 标识时间窗内可视为常量的字段。
  • ejit_period / ejit_period_arr 描述时间窗对象。
  • ejit_period_arr_ind 作为特化维度参数。
  • ejit_period_lc 插入激活 / 失活生命周期钩子。

Pass AOT Pipeline

PASS1: EJitRegisterBitcodePass（早期） 在标准优化前提取 ejit_entry 传递闭包；预优化 bitcode；恢复 !ejit.may_const；嵌入 ELF section。
PASS2: EJitRegisterPeriodPass 生成时间窗变量 / 数组注册代码，为运行时 PeriodArrayRegistry 提供基地址与元信息。
PASS3: EJitWrapperGenPass 在原 ejit_entry 函数入口插入单函数 Wrapper：先查 JIT 版本，失败则走原 AOT 逻辑。
PASS4: EJitPeriodHandlerPass 在生命周期函数中插入 activate / deactivate；失活时触发版本切换与缓存失效。
标准 O2/O3 + 目标代码生成 优化 Wrapper 和 fallback 路径，最终输出目标代码、注册构造函数和内嵌 bitcode。

原则 安全保守特化

Metadata 是软注解：丢失只会减少特化机会，不影响正确性。可常量化字段同时保存在 load metadata 和 GV-level 偏移列表中，形成双保险。

② 产物与初始化桥接：ELF Section → Runtime Store

ELF 编译产物

  • .ejit.bitcode：每个入口函数对应的闭包 bitcode。
  • llvm.global_ctors：自动注册 bitcode、period array、外部符号。
  • Wrapper 生成 funcIdx + dims 形式的紧凑 cache key。

Init 注册生命周期

OS / Loader 装载 ELF bitcode section、全局变量、构造函数随目标程序一起进入内存。
构造函数自动注册 ejit_auto_register() 写入 EJitRegistrationStore 单例，暂存 bitcode、period、symbol 信息。
应用调用 ejit_init() 消费 RegistrationStore，创建 Engine、Cache、CompileDriver、PeriodRegistry、BitcodeTracker。
裸核替代路径 可使用静态注册表 __ejit_registry_bitcode[] / __ejit_registry_period[]，避免依赖动态构造。

Fallback 运行时安全边界

Wrapper 的默认行为是“先尝试 JIT，任何未命中、未激活、编译中、内存不足或失效情况都返回 NULL 并执行 AOT 原逻辑”，保证功能正确性优先。

③ Runtime：缓存、编译、链接与执行

Runtime 核心对象

EJitCompileDriver统一 getOrCompile 入口：查 cache、触发同步 / 异步编译。
EJitCache按 funcIdx + dims + version 保存函数指针，支持 LRU 与失效。
EJitOrcEngine封装 LLJIT、IRTransformLayer、JITLink 以及符号解析。
EJitJITLinkMemoryManager固定 slab / code pool，写入后切换 RX，适配嵌入式内存约束。
PeriodArrayRegistry维护时间窗对象基地址、激活状态和版本。
BitcodeTracker按函数索引定位可 JIT 的 bitcode 闭包。

JIT IR Transform Pipeline

参数维度替换 将 ejit_period_arr_ind 参数替换为实际 dim 值，形成实例化 IR。
InstCombine + Inline 清理 IR，并通过内联让 may_const load 的 GEP 链可回溯到根全局变量。
PASS6: EJitStructFieldPass 确认时间窗 active 后读取字段值，把可常量化 load 替换为 LLVM 常量。
标准优化 L1/L2/L3 SCCP、DCE、CFG Simplify、Loop 优化等基于常量折叠生成高效特化代码。
JITLink + Code Pool 链接、重定位、分配代码内存，返回可执行函数指针并写入 cache。

Invalidate 时间窗失效

ejit_deactivate 切换实例 version；cache entry、in-flight task、queue task 均按 version 校验，自然 miss，旧代码不再被新请求命中。

源码标注

开发者用 ejit_entry、ejit_may_const、ejit_period* 描述“哪些函数可特化、哪些数据在时间窗内稳定”。

AOT 产物

Pass 提取 bitcode 闭包，生成 Wrapper 和注册代码；最终程序同时包含 AOT fallback 与 JIT 所需 IR。

运行时特化

Wrapper 根据维度和时间窗状态请求 JIT；命中 cache 直接跳转，未命中先 fallback 并异步生成特化版本。

SRE 异步 Taskpool 调度模型

Wrapper 热路径调用 ejit_compile_or_get，不阻塞应用线程；无可用 JIT 时立即 fallback。
SwitchController检查 Off / Async 模式、period active 状态和实例 version。
TaskPoolCache32 桶 unordered_map + 独立 RwLock；try-read 失败立即 fallback。
DedupTable按 funcIndex / key 进行 CAS 占位，避免重复提交同一编译任务。
MPSC Queue多 producer、单 consumer 无锁队列；SRE 平台上固定单 worker。
EJitWorker后台 SRE task 消费队列，调用 compileFn_ 生成机器码。
Cache.put编译成功写入 cache；后续相同 key / version 直接命中特化函数。

汇报重点 1：双阶段设计

AOT 负责“可 JIT 资产准备”：提取 bitcode、保留 metadata、生成 wrapper 和注册逻辑；Runtime 负责“按时间窗状态特化”。两者通过 ELF section 和 RegistrationStore 解耦。

汇报重点 2：正确性优先

任何无法确定安全性的情况都回退 AOT：metadata 丢失、period 未激活、cache miss、正在编译、内存不足、version 失效都不会破坏原程序语义。

汇报重点 3：嵌入式约束

运行时采用固定 code pool / slab、可裁剪 LLVM 后端、单 worker 异步调度、有限锁粒度 cache，以适配 CPU、内存和实时性约束。
