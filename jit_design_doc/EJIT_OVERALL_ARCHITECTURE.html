A. 初始化与时间窗管理
init注册与初始化（ejit_init）
  • 消费 EJitRegistrationStore（ctor 暂存）或遍历静态注册表
  • EJitFuncRegistry：按函数名分配 dense funcIndex
  • EJitLifecycleRegistry：按 periodName 分配 dimType 槽位
  • PeriodArrayRegistry：periodName → vector{varName, baseAddr, size}
  • BitcodeTracker：funcName → bitcode 数据（只读，按需 parse）
  • 创建 EJitOrcEngine（LLJIT + 自定义 MemoryManager）
  • 创建 CompileDriver + TaskPool + Worker
  • 冻结 registration · Async 启动 worker · Shared 模式 owner 选举
▶
state时间窗状态管理
  • EJitRuntimeState：核心状态机
  • ejit_activate(name, idx)：
    设置 (dimType, instanceId) → Active
    release fence（保证全局变量写入对编译线程可见）
  • ejit_deactivate(name, idx)：
    CAS(enabled 1→0) + 单调 version++
  • 键 = (dimType, instanceId)，无数组指针维度
  • 状态：Inactive → Active → Invalid
▶
wrapperWrapper 热路径（AOT 插入的入口代码）
  • 从 per-lifecycle global 加载 dimType → 构造 ejit_dim_pair_t dims[]
  • 调用 ejit_taskpool_compile_or_get(funcIndex, dims, numDims, &outFn, &outBucket)
  • ① SwitchController：检查每维 enabled + version 匹配
  • ② TaskPoolCache.lookup：hash(funcIndex,dims)→bucket→slot scan（identity/version/generation 匹配）→ 返回 {fnPtr, bucket}
  • ③ 命中 → 调 fnPtr(args) → ejit_taskpool_release_read(bucket)
  • ④ 未命中 → TaskQueue.tryEnqueue (dedup CAS) → fallback（继续执行原 AOT 逻辑）
  • 同步模式：未命中时调用线程内联编译 → 返回 fnPtr；异步模式：入队返回 PENDING
B. 后台编译 Worker · JIT 特化流水线（EJitOrcEngine / LLJIT）
workerEJitWorker
  • 单消费者 MPSC（Vyukov 环 1024 slot）
  • tryDequeue → checkpoint₁ 比 version
  • → CompileCallback → 编译
  • → checkpoint₂ 比 version → publish
  • publish gate：版本不匹配则丢弃结果
  • queue full → 回滚 dedup，返回 fallback
  • Sync 模式：调用线程执行 compileCold，不经过 worker 队列
▶
JITIRTransformLayer 特化流水线（EJitOptimizer::runPipeline）
  • 0. Bitcode 按需加载（BitcodeTracker → parse Module）
  • 1a. preReplacePeriodIndices：EJIT_DIM("name") 参数 → ConstantInt（replaceAllUsesWith）
  • 1b. InstCombine：折叠 zext / GEP 常量链、清理 PHI
  • 1c. PASS6 EJitStructFieldPass：扫描 !ejit.may_const load → 从进程内存读取运行时值 → 替换为 Constant（双机制：per-load metadata 主路径 + GV 偏移列表回退）
  • 1d. IPSCCP（runInterproceduralPropagation）：内部化非 entry 定义 → 跨函数常量传播（替代 JIT 侧 Inline）
  • 1e–1f. 二次 InstCombine + StructFieldPass（对 callee 传播结果再做一轮）
  • 2. LowerExpect：降低 llvm.expect intrinsic
  • 3. buildFunctionSimplificationPipeline（O1/O2/O3 预建缓存）：
    L1→O1: SCCP+DCE
    L2→O2: +GVN+LICM+CFGSimplify
    L3→O3: +LoopUnroll+Vectorize
  • 4. 三次 StructFieldPass + cleanup（InstCombine/SCCP/SimplifyCFG/ADCE）：循环展开后新暴露的常量下标数组访问
▶
codegenIRCompile → ObjectLinking
  • IRCompileLayer：LLVM IR → 目标机器码（Object）
  • ObjectLinkingLayer（JITLink）：链接 + 重定位
  • PreFixup：EJitLinkOptimizationPlugin — AArch64 近目标分支松弛（stub→GOT→target → 直接 B/BL，±128MiB 内）
  • PostFixup：EJitLinkDiagPlugin — 审计所有分支重定位
  • EJitCodePoolMemoryManager：从 CodePool bump 分配 → write → finalize（4K 页 RW→RX 密封 enable_ex）
  • lookup → ExecutorAddr → fnPtr
C. Inline Cache 模式（可选，-ejit-inline-cache，frame-less hit path）
icacheFrame-less 命中路径
  • per-function @__ejit_icache_fn_<name> 固定数组 [D]^numDims
  • 命中路径：GEP[dimVals] + load slot + null-check + tail call
  • 无栈帧、无 compile_or_get 调用、无 release_read
  • llvm.expect(hit, true) 提示命中分支
  • 实测：0 维 4 cycles / 1 维 5 / 2 维 6 / 3 维 8 / 4 维 9（aarch64_be, -Os）
▶
missMiss 慢路径
  • miss → tail call <name>_miss（noinline，自带栈帧）
  • MissFn 内：funcidx guard → compile_or_get → dispatch / fallback
  • MissFn 继承 F 的 target-cpu/features/tune-cpu + section
D. 运行时基础设施（并发安全 · 代码内存 · 裸核/SRE 抽象 · 后端裁剪）
cache代码缓存
  • 32 bucket · per-bucket EJitRwLock
  • 16 slot/bucket · slot = {identity, version, generation, codeRange, fnPtr}
  • read-token：lookup 不释放，release_read 释放（seqlock NO_RECLAIM 则为 no-op）
  • publish：先写 identity/version/codeRange，再发布 Ready；spin readers==0 后覆盖
  • cacheKey = hash(funcIndex, dims[]) % 32
pool代码内存池
  • EJitCodePoolManager：2MiB 对齐 bump allocator
  • 来源：SRE_MemDbgAlloc（动态）或固定区域 [__ejit_code_start, __ejit_code_end)（链接脚本）
  • 写时 RW（enable_rw），finalize 密封 RX（enable_ex）
  • 固定模式强制 shared taskpool（CMake + 源码双守卫）
  • 边界检查 · 失败回滚 restoreRxRange（W^X 安全）
  • 密封池不重写 · 溢出开新池 · 废弃 slab RX 恢复
sreSRE 平台抽象
  • EJitAtomic（无 std::atomic）· EJitRwLock
  • EJitSreTask（无 std::thread）· Vyukov MPSC 队列
  • 裸核修正：禁用进程符号链接、固定 triple、forceStaticRegistry
  • 可选 EJIT_SRE_SHARED_TASKPOOL：跨核共享 taskpool · owner 选举 · 共享 POD 状态
  • 可选 EJIT_SRE_TASKPOOL_NO_RECLAIM：seqlock load-only hit
trimLLVM 后端裁剪
  • EJitPassBuilder：精简 ~20 analyses
  • 移除：SVE/AdvSIMD/GlobalISel/MT 等
  • 提取单 .o（lipo extract→gc-merge→merge）
  • 仅 ARM/AArch64 目标
  • 禁用 dlopen/dlsym · 固定 triple

⏳ 缓存失效（deactivate 触发，三层惰性，不遍历表项）

deactivate→version++→ ① Cache lookup 版本不符 → miss→ ② Queue checkpoint₁ 丢弃→ ③ In-flight checkpoint₂ 不 publish
物理回收：同 cacheKey 覆盖于 publish spin readers==0 后。freeCode 不在失效路径。NO_RECLAIM 下永不回收。

🛡️ Fallback 容错原则

  • 所有 JIT 失败（Bitcode 解析/特化/OOM/越界/空指针/异步 pending）→ 继续执行原函数 AOT 逻辑
  • 单函数混合方案：无独立 fallback 函数，失败即 fall-through
  • 错误日志环形缓冲区（32 条）
  • 核心原则：绝不崩溃，仅记日志降级

🔑 关键设计决策

  • 特化维度 = 时间窗常量 + 结构体字段索引（非基于参数值）
  • 单函数 Wrapper（非独立函数）
  • !ejit.may_const 软标注（丢失仅错过一次特化）
  • taskpool 固定 bucket + read-token 并发安全
  • 两阶段 AOT：早期提 Bitcode / 晚期插桩
  • 4K 页级 RW→RX 密封 · 代码池 bump 不回收
  • IPSCCP 替代 JIT 侧 Inline（减轻编译负担）

⚡ Inline Cache 约束与安全

  • 维度 ≤ EJIT_ICACHE_MAX_DIMS(=4)，超限编译报错
  • EJIT_DIM 参数值 < D（无运行时边界检查，契约保证）
  • NO_RECLAIM 下 fnPtr 永不悬空（永不释放）
  • reclamation safety gate：有 code releaser 时自动关闭 cache
  • per-core private slot：无跨核 RMW，无 release_read
