EmbeddedJIT 总体逻辑架构设计图

基于时间窗常量的运行时特化编译系统：AOT 阶段提取带元数据的 Bitcode 并插桩 Wrapper，运行时按时间窗实例 JIT 特化、缓存机器码，失败回退 AOT。

⬛ 用户标注属性（Clang 前端，6 个）
EJIT_PERIOD_CONST 成员可常量化 EJIT_IN_PERIOD(static) 运行期不变 EJIT_IN_PERIOD_ARRAY(name) 数组时间窗 EJIT_ENTRY JIT 入口函数 EJIT_DIM(name) 特化维度参数 EJIT_PERIOD_GUARD(name) 生命周期管理函数
⬛ 运行时 C API（libejit.a）
ejit_init / shutdown ejit_activate / deactivate(_all) ejit_is_active ejit_taskpool_compile_or_get ejit_taskpool_release_read ejit_register_symbol ejit_set_compile_mode

A. 初始化 · 时间窗状态 · 热路径入口
init注册与初始化
  • ejit_init 消费 EJitRegistrationStore
  • EJitFuncRegistry：按名分配 funcIndex
  • EJitLifecycleRegistry：分配 dimType 槽
  • PeriodArrayRegistry：name→baseAddr
  • BitcodeTracker：name→Bitcode（只读）
▶
state时间窗状态 EJitRuntimeState
  • ejit_activate/deactivate(name, idx)
  • 键 = (dimType, instanceId)，无数组指针维度
  • 状态 Inactive→Active→Invalid + 单调 version
  • deactivate：CAS(enabled 1→0) + version++
▶
hotWrapper 热路径 → EJitTaskPool
  • ejit_taskpool_compile_or_get(funcIndex, dims[], outFn, outBucket)
  • ① SwitchController 检查每维 enabled + version
  • ② TaskPoolCache.lookup（tryRead bucket + version 比较）
  • 命中→ 返回 {fnPtr, bucket}；调用 fnPtr 后 release_read(bucket)
  • 未命中→ TaskQueue.tryEnqueue（dedup CAS + Vyukov 入队）→ 返回 fallback（执行 AOT 原逻辑）
B. 后台编译 Worker · JIT 特化流水线（EJitOrcEngine / LLJIT）
workerEJitWorker
  • 单消费者 MPSC（Vyukov 环 1024）
  • tryDequeue → checkpoint₁ 比版本
  • → CompileCallback → 编译
  • → checkpoint₂ 比版本 → publish
  • 同步模式：setNumCompileThreads(0)，调用线程 compileCold 内联编译
▶
JITIRTransformLayer 特化流水线
  • 1. 加载 Bitcode（BitcodeTracker → Module）
  • 2. 参数替换：EJIT_DIM 参数 → 运行时常量
  • 3. InstCombine：折叠 zext/GEP 常量链、清 PHI
  • 4. Inline：展开跨函数 GEP 链
  • 5. PASS6 EJitStructFieldPass：!ejit.may_const load → 运行时常量（per-load 元数据 / GV 偏移回退双机制；baseAddr + accumulateConstantOffset → memcpy）
  • 6. EJitOptimizer：L1(SCCP+DCE) / L2(+Inline+CFG) / L3(+LoopUnroll)
▶
codegenIRCompile → ObjectLinking
  • IRCompileLayer：LLVM→Object
  • ObjectLinkingLayer（JITLink）
  • EJitCodePoolMemoryManager：从代码池 bump 分配
  • finalize → 4K 页密封 RW→RX（enable_ex）
  • lookup 返回 ExecutorAddr → fnPtr
C. 运行时基础设施（并发安全 · 裸核/SRE 抽象）
cache代码缓存 EJitTaskPoolCache
  • 32 bucket，每 bucket 独立 EJitRwLock
  • read-token：lookup 不释放，调用方用完 release_read
  • publish：spin 该 bucket readers==0 后覆盖旧 fnPtr
  • cacheKey = hash(funcIndex, dims[])，bucket = key % 32
pool代码池 EJitCodePoolManager
  • 2MiB 对齐 bump allocator，来源 SRE_MemDbgAlloc 分区 8
  • 禁用 malloc/mmap；写时 RW，密封后 RX
  • 密封池永不重写，溢出则新开池（可靠优先于碎片）
  • 跨核共享：每核 split_2m_to_4k + per-page enable_ex 记忆化
sreSRE 平台抽象 EJitSrePlatform
  • EJitAtomic（无 std::atomic）/ EJitRwLock
  • EJitSreTask（无 std::thread）/ Vyukov MPSC 队列
  • 裸核修正：禁用进程符号链接、固定 triple、forceStaticRegistry
  • 可选 EJIT_SRE_SHARED_TASKPOOL：owner 选举跨核共享
  • LLVM 后端裁剪：移除 SVE/AdvSIMD/GlobalISel 等，lipo 合并 ejit.o

⏳ 缓存失效（deactivate 触发，三层惰性，不遍历表项）

deactivate→version++→ ① Cache lookup 版本不符 → miss→ ② Queue checkpoint₁ 丢弃→ ③ In-flight checkpoint₂ 丢弃不 publish
物理回收：同 cacheKey 覆盖于 publish；旧 fnPtr 在 readers==0 后释放。freeCode 不在失效路径。

🛡️ Fallback 容错原则

  • 所有 JIT 失败（Bitcode 解析 / 特化 / OOM / 越界 / 空指针 / 异步 pending）→ 继续执行原函数 AOT 逻辑
  • 单函数混合方案：无独立 fallback 函数，失败即 fall-through
  • 核心原则：绝不崩溃，仅记日志降级

🔑 关键设计决策

  • 特化维度 = 时间窗常量 + 结构体字段索引
  • 单函数 Wrapper（非独立函数）
  • 元数据软标注，丢失仅错过一次特化
  • taskpool 固定 bucket + read-token 并发安全
  • 两阶段 AOT：早期提 Bitcode / 晚期插桩
  • 4K 页级 RW→RX 密封，密封池不重写
