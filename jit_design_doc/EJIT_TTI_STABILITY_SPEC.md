# EJIT TTI 稳定性观察与动态特化规格

日期：2026-10-01。目标分支：`ejit_dev_spec5`。
审阅基线：`e09df842062735ba9f6279ae7d1c5b43fd723bec`。
状态：需求与设计提案，未实现；本 PR 只交付规格，不表示业务前提已确认或上板验收已完成。

## 1. 需求与范围

TTI 相关配置可能约每 10 秒变化一次，但该周期不是保证。JIT 自动观察已登记字段，只有观察稳定达到配置窗口后才允许特化编译；持续波动时保持通用执行，不反复排队。配置变化后停止使用旧特化，再观察和异步重编。

已确认 `1 TTI = 500 us`。业务提出最多 `5 TTI = 2500 us` 的容错，但容错对象仍待确认：发现变化、停止新调用使用旧值，或全部旧调用完成。本文给出可验收的时限定义，不承诺在 2500 us 内完成 LLVM 编译。

本提案适用于允许受控短时旧值的、显式登记的标量配置。它是对 [SPEC4.md](SPEC4.md) 时间窗模型的选择性扩展，不修改现有 `ejit_may_const` / `ejit_period_const` 的不变性合同。现有激活窗内可直接冻结的字段不会自动变为轮询字段，现有 `static` 或初始化后永久不变的字段也不能直接套用本模式。

每次观测相同只证明观测历史，不能证明未来不变。允许可变配置特化的依据必须同时包括：明确的字段授权、一致读取协议、稳定准入条件、持续失效机制及业务认可的旧值容忍范围。

## 2. 参数与时间定义

| 项目 | 定义 | 状态 |
| --- | --- | --- |
| `ttiPeriodUs` | TTI 周期，500 us | 已确认 |
| `stableWindowTtis` (`W`) | 准入前至少观察稳定的完整 TTI 间隔数 | 可配置；建议讨论起点 5，待业务确认 |
| `maxStaleTtis` (`D`) | 配置更新后允许旧配置行为持续的最大 TTI 间隔数 | 需求候选值 5，具体适用字段与截止含义待确认 |
| `pollIntervalTtis` (`P`) | 同一观察域的检查周期 | 首版建议 1；实际最大间隔含调度延迟 |
| `readBudget` / `monitorBudget` | 一致快照读取与全部域检查的最大工作量 | 需基于目标机测量配置 |
| 编译、快照、代码缓存预算 | 并发尝试、字节数、保留代际及重试限制 | 实现前给出明确上限 |

首版要求 `W >= 1`、`P = 1`、`D >= 0`，不合法或不支持的配置须明确拒绝。`D = 0` 或要求立即生效的字段不能使用有延迟的轮询失效合同，须采用业务同步更新/入口验证协议，或保持通用读取。

使用不回退的 TTI 序号或单调时钟。原始 `slotNo` 及其 `%5/%10` 会回绕，不能作为窗口计时或配置代际。

稳定窗口从首个有效样本 `q0` 开始。默认每 TTI 一次有效观察，只有到 `q0 + W` 且期间每个检查点均有效、整体值一致，才允许编译。`W=5` 时需要边界 `q0..q0+5` 的 6 个样本，覆盖完整 2500 us；连续 5 个边界样本只覆盖 2000 us。重复 entry 调用、重复 tick 或同一 TTI 的多次读取不增加稳定时间。

漏 tick、TTI 序号倒退、读取失败或观察域未就绪都打断连续观察。首版清零稳定窗口、关闭该域特化并回退通用路径；不能把漏掉的时间补算为稳定。若要求硬时限，系统还须在检查调度丢失时按截止时间阻止旧特化，不能等到恢复轮询才失效。

## 3. 业务启用合同

启用前必须逐观察域记录以下选择；未填写时保持通用路径，不因本规格建议值默认授权旧值：

1. 精确字段集合、类型、地址与有效期，以及允许特化的 entry 和依赖实例。
2. 稳定语义：版本持续不变，还是仅要求 TTI 边界的值观测相同。
3. 每个字段允许的旧值窗口；哪些字段必须立即生效，哪些允许最多 5 TTI。
4. 截止含义：只禁止新的旧版本调用，还是要求旧调用产生的最后一次业务效果也结束。
5. 更新发布协议、一致读取方式、跨核映射和内存可见性保证。
6. 通用路径如何取得当前合法配置；它在不稳定、编译中、失败和资源耗尽时是否满足业务时限。
7. 业务调用最大执行时间，以及旧快照字段与当前动态字段、store、副作用混用是否在旧值窗口内可接受。

“大概每 10 秒变一次”用于评估收益，不代替以上合同。`W` 与 `D` 分别配置，不能因为容错为 5 TTI 就自动确定稳定窗口也为 5 TTI。

## 4. 观察域与字段描述

`ObservationDomain` 是一组必须一起读取、一起判稳、一起失效的特化依赖。首版按现有生命周期实例建立，例如 `cell[3]`；所有依赖该域的 entry 共用观察结果，每域每检查点最多一次有效采样。

全局配置建立全局观察域，影响所有实际依赖它的版本。同时依赖 cell、TRP 或其他配置域的 entry 必须携带完整依赖向量，只有全部依赖仍稳定有效才可发布和调用。不得假定两个域总是一起更新。

字段描述至少包含类型/位宽、合法源范围、布局、所属域、读取协议及授权信息。地址、对象生命期或布局改变也构成域变更。来源不明、无法稳定读取、越界及未初始化的字段拒绝本模式。首版不推断任意 borrowed pointer、动态指针链或未枚举别名的依赖。

只比较获准字段的类型值，不对结构体 padding 作 `memcmp`。整型按位宽比较；浮点按位比较，包括负零和 NaN payload。处理大端目标时按目标 DataLayout 解码和构造常量。摘要可用于筛选，最终判稳/复用仍比较完整字段值及合同，不以 hash 相同代替精确比较。

多个字段组成一个一致快照，不能分别积累稳定次数后拼成从未同时存在的配置。普通实时字段不参与冻结，其 load/store 保持原对象和现有语义。volatile、atomic、MMIO、函数指针或有地址身份语义的读不能因本观察机制被消除；监测协议自身可以使用原子变量，业务中的原子 load 仍按原语义执行。

## 5. 一致读取与两种稳定语义

### 5.1 带版本的配置发布：首选

写入方提交一致配置后发布 `SourceRevision`。它必须覆盖该域所有获准字段与其布局/地址变化，在有效会话内不回绕到仍可匹配的旧版本。观察方取得关联的完整字段快照和 revision；读取期间出现更新则本次观察无效。

可采用有生命周期保护的不可变配置对象发布，或有明确同步语义的受保护复制。若使用 sequence/retry 方案，所有并发访问必须符合目标语言及平台内存模型；普通 C/C++ 非原子并发读写不能仅靠序号复核变成合法访问，也不能只加 `volatile`。

本模式要求值与 revision 均持续一致。即使值 `A -> B -> A`，revision 的变化也会打断观察、使旧尝试失效。与获准字段无关的更新可使用独立 revision 减少过度失效，但不能漏掉任何真实依赖。

### 5.2 仅比较一致字段快照：业务显式选择

写入方不提供 revision 时，JIT 可每 TTI 通过合法的一致读取协议比较字段快照。本模式只保证采样时刻观察到相同值，无法发现两个样本间的 `A -> B -> A`。

只有业务明确接受此观测语义、并且中间变化没有必须记录的代际/副作用要求时才能启用。没有 revision 不代表可以无同步扫描正在写入的结构体。只比较指针不能检测原对象内容变化。

两种模式都在发布前取得新的一致样本；发布样本不能代替缺失的历史检查点或缩短稳定窗口。若业务需要证明期间没有发生任何更新，必须选择 5.1 或提供等效更新记录。

## 6. 生命周期状态机

| 状态 | 业务执行 | 允许的控制动作 |
| --- | --- | --- |
| `UNREADY` | 通用路径 | 等待源对象及合同就绪 |
| `OBSERVING` | 通用路径 | 每 TTI 采样；变化/失败重置窗口 |
| `ELIGIBLE` | 通用路径 | 稳定窗口达标，受预算控制提交编译 |
| `BUILDING` | 通用路径 | 后台编译；继续观察，变化立即废弃尝试 |
| `ACTIVE` | 满足完整准入检查时调用特化 | 继续观察；变化关闭入口并回到 `OBSERVING` |
| `BACKOFF` | 通用路径 | 失败或资源不足后有界退避；持续监测 |

状态属于一个明确的 `DomainEpoch`。每次观测变化、生命周期停用、地址/合同变更或硬观察故障都撤销旧域有效性并建立新代际，避免旧回调操作重建后的状态。

同一 entry、依赖向量及代际最多一个有效编译尝试。值持续变化时不得反复积累未执行请求；新稳定代际替代旧请求，无法取消的 LLVM 编译允许结束后丢弃。一次尝试失败不得在每次业务调用上重试，重试受退避和预算控制。

约 10 秒到期本身不触发失效；只有依赖变化或上述故障才触发。相同值且版本语义也未变化时保留现有代码。

## 7. 变化检测与 5 TTI 截止

定义 `t_change` 为业务一致配置更新的发布时刻，`t_detect` 为 JIT 首次有效观察到变化的时刻，`t_block` 为全部目标调用核已禁止新调用进入旧版本的时刻。

若合同选择“停止新的旧版本调用”，验收要求：

```text
t_block - t_change <= D * 500 us
最大检测间隔 + 检测处理时间 + 跨核入口关闭时间 <= D * 500 us
```

候选 `D=5` 的上限为 2500 us。时间从实际变化算起，不能从发现变化时再额外给 5 TTI。轮询周期、最大调度抖动、共享内存可见性及快路径关闭开销都占该预算。每 TTI 检查一次有利于留出余量，但仅设置周期不构成硬时限证明。

如果业务要求“全部旧配置效果结束”，还需包括已进入旧代码的最长执行时间和下游效果生效时间。JIT 不强行中断正在执行的机器码；必须有可证明的完成界限或业务安全点。无法提供界限的域不能声称满足该更强时限。

发现变化时立即执行逻辑失效，无需等待新窗口达标或新编译完成。编译期间及不稳定阶段由通用路径读取当前一致配置。通用路径的数据同步同样由第 3/5 节合同保证。

长期无业务调用的实例也不能靠调用次数推进监测。可选择调度器每 TTI 驱动全部在用域，或在首次恢复调用时先验证样本新鲜度/代际，再允许特化。看门狗或入口新鲜度检查必须覆盖监测超时。

## 8. 编译快照、有效性与发布

稳定准入后取得只包含获准字段的不可变 `CompileSnapshot`，其生命周期覆盖编译及所有使用者。编译器只从该快照取得监测字段的常量，不在优化中重新读取会变化的业务对象。此项需要明确实现支持，不能只在现有 pass 外套轮询就认为完成。

快照不替代原对象地址，不能重定向业务 store 或普通动态 load。原对象被删除或重定位仍通过生命周期协议失效，不因旧快照保留而授权继续访问原对象。

请求、profile、缓存项及回调携带至少以下身份：

```text
entry + source/schema + compile policy
完整生命周期依赖 + DomainEpoch 向量
CompileSnapshot 身份 + SourceRevision（若采用版本语义）
AttemptToken + runtime/shared-taskpool generation
```

`DomainEpoch` 是逻辑配置代际，`AttemptToken` 是一次工作尝试，运行时重启 generation 是服务代际；三者不能混用。队列去重释放也必须针对原 token，旧完成回调不能清除新尝试的占位。

至少在入队、真正编译前、进入后续 tier 编译前及发布前校验身份。发布前再次读取一致源快照，精确匹配值、revision 和完整依赖；任何不匹配都丢弃产物并触发失效/重新观察。

最后检查与可调用入口安装必须同更新/失效协议协调，形成一个有序的提交。禁止“先检查代际、失效线程更新、再无条件写入旧函数指针”的窗口。安装中的候选代码在提交前不可被业务调用；提交后变更仍由持续监测与截止协议处理。

资源准备或跨核代码可见性失败时保持通用路径，不能发布半准备好的代码。代码可调用仍遵守现有封页、I-cache 维护及目标核准备协议。

## 9. 快路径与跨核失效

观察由有界控制路径每 TTI 驱动，业务入口不逐个 `may_const` load 比较值或执行完整域扫描。稳定状态只允许增加经测量的入口有效性/新鲜度检查，或采用满足同一截止的集中失效协议。

当前 spec5 的共享 inline cache / L0 快路径可能在命中时绕过 taskpool lookup，因此仅使普通 cache miss 不足以保证截止。实现必须证明所有调用路径都参与失效：wrapper inline cache、L0/direct dispatch、taskpool 缓存、正在填充的槽位和延迟发布。

可在入口检查域代际/准入状态，或扩展已有跨核 drain/dispatch epoch 协议，使共享槽位不会在关闭后被旧 resolve 回填。选择由实现评审和目标机开销决定，本规格不预先规定额外分支数量。无论采用哪种方式，所有路径须满足第 7 节同一上限。

外部长期缓存的裸 JIT 函数指针不能绕开准入检查直接调用；须遵守有效借用协议、使用受控跳板，或禁止这种调用形态。已进入代码的调用可按合同完成，代码内存须保留至所有执行者退出。

各核共同观察同一业务对象时共享一致的观察域状态与 epoch，不按核各自独立积累稳定次数再发布同一份代码。若实际配置为核私有对象，域/绑定身份必须包含对应对象；不能仅因 cell 号或地址数值相同就共享观察结果。

## 10. 与已有功能的关系

### 10.1 生命周期与原有标注

优先复用现有生命周期失效、异步队列和发布机制，但需要为观测字段增加显式授权、快照读取及准入描述。单独调用现有 activate/deactivate 不自动证明全部源借用、业务同步或 5 TTI 截止已经满足。

停用实例后旧观察结果全部无效，重新激活须重新就绪并观察。监测注册失败、描述冲突或依赖超出支持范围时关闭本模式，报告原因并使用通用路径。

### 10.2 PGO

稳定窗口达标才允许任何依赖新快照的特化，包括插桩 T1。TTI 观察次数不能计入 PGO dispatch 配额；PGO 继续只记录真实 T1 执行。

T1/T2 使用同一快照和依赖身份，持续监测覆盖 T1 采样、T2 排队、编译和发布全部阶段。变化使受影响 T1/T2 尝试及 profile 无效；首版不跨配置代际复用 profile。

64 次采样若由所选基线配置，仍是独立的 PGO 参数。稳定窗口达标不保证 PGO 立刻达到配额，不保证 T2 在 5 TTI 内出现。审计诊断开关也不能替代正常在线 PGO。

### 10.3 reuse、小表及 slot/phase

本规格不依赖尚未合入目标基线的 PR230/231 或 slot 派生维度实现，后续组合需独立接线和验收。

与 reuse 组合时，逻辑有效性仍逐依赖维护；物理代码相同不允许一个实例的稳定历史代替另一个实例。跨代际重用旧物理代码必须重新验证完整快照、绑定、生命周期与调用权限，不能仅凭值 hash 命中恢复旧准入。

与小表组合时，常量字段、消轴证明和表值都纳入监测依赖；变化需使全部受影响代码/表合同失效。未就绪或不稳定行不能参与全等证明，表行也不能在业务并发读取时无协议改写。

`slotNo %5/%10` 是选择版本/表行的派生索引，稳定观察是配置变化管理，两者独立。phase 特化存在时，同一域配置变化须失效所有依赖它的 phase 版本；原始 slot 参数仍保持动态。

判稳始终比较同一字段坐标，不把相邻 TTI 命中不同 phase 的不同值当成配置变化。首版如监测 phase 数组，则每次取得已登记范围内的完整一致字段向量，并与上一向量逐坐标比较；跨 phase 本来不同但各格稳定的配置可以通过窗口。扫描容量计入预算，未初始化的 phase 不参与读取，也不能据此授权覆盖它的版本。

## 11. 资源预算与长期运行

每 10 秒变化一次对应每小时约 360 个变化事件，实际还可能更频繁。预算同时覆盖观察域/字段、快照、队列、T1/profile、T2 代码和失效后仍被借用的资源。

所有容量都有上限；超限保持通用路径并计数，不允许无界积累、阻塞 TTI 或循环强制编译。旧快照等待读取/编译借用结束，旧代码等待执行借用结束后方可回收。取消一个逻辑请求不代表已可释放对应 LLVM 对象或代码。

`NO_RECLAIM` 或仅 bump 分配的部署必须明确有限运行预算及耗尽行为：停止新特化、继续通用执行；若产品要求无限期持续重编，则代码池/相关资源回收或有界复用是启用前置条件，不能用“每次编译成功”宣称长跑闭环。

反复出现的相同配置可按完整身份精确比较重用物理代码，但稳定窗口、新逻辑代际及第 8/9 节准入仍须重新完成。首版不要求实现该优化。

## 12. 集成接口边界

首版需要三类能力：登记观察域/字段及业务合同；由 TTI 调度点驱动检查；读取状态、失效原因和统计。JIT 负责比较、窗口计时、编译准入及失效，业务不需每 10 秒显式调用编译。

可选写入通知能够提前失效，但不能绕过稳定窗口。一致快照读取可以由业务适配器提供，或由 JIT 使用已证明的共享读取协议。接口必须有界、不能在 TTI 热路径调用 LLVM 或等待编译。

本 PR 不发布新的可调用 API/attribute 名称。实现阶段确定前端 metadata、注册描述和 C ABI，禁止把草拟名字当成现有 spec5 能力。新增共享布局时评审并更新 ABI/fingerprint；不得静默扩展原有未版本化配置结构。

启用采用显式 opt-in。未注册该模式的字段继续使用原合同。产品启动构造、每核 runtime 初始化和共享 worker 配置依照现有部署约定，不由每 TTI 监测重复执行。

## 13. 诊断与验收

每域诊断至少显示：合同/模式、域及依赖身份、W/D/P、当前状态和 epoch、revision、首样本与最近有效样本 TTI、观察间隔上限、稳定重置原因、有效 attempt、已发布 tier 及入口有效性。

聚合计数至少包括：有效/失败/漏 tick 观察、值/revision 变化、稳定准入、去重/退避、过期请求/发布拒绝、通用回退原因、监测开销、失效传播时间、快照及代码当前/峰值字节。TTI 热路径只更新有界计数，打印由调测路径按需执行。

| 测试 | 必须观察的结果 |
| --- | --- |
| W=5，q0..q0+4 相同 | 不准入；到 q0+5 才允许提交 |
| 同一 TTI 多次调用/重复 tick | 不推进窗口，不重复排队 |
| 值每 TTI 变化或多字段交替变化 | 持续通用执行，无特化尝试积累 |
| 观察中、排队中、编译中、T1 采样中、发布竞争中变化 | 旧尝试不能覆盖新状态，旧 token 不释放新占位 |
| 已运行特化后变化 | 在约定 D 内关闭所有新旧版本调用；通用路径正确 |
| 变化发生在两次检查之间、最坏调度抖动和跨核延迟 | 从 t_change 测量截止，不从 t_detect 重算 |
| 漏 tick、读取失败、长期无调用、恢复调用 | 无虚假稳定，无过期特化入口；硬截止有看门狗/入口保障 |
| A -> B -> A | revision 模式必须打断；值模式按明确业务合同验收 |
| 多字段一致快照、对象迁移/停用/重激活 | 无混合配置，无悬空访问，重新观察 |
| cell/TRP/全局及多核共同依赖 | 受影响版本全部失效，不影响无关实例；全路径无旧回填 |
| 各 phase 取值不同但每格稳定、单格配置变化 | 逐坐标判稳不误重置；单格变化使全部实际依赖它的版本失效 |
| IR 与目标大端执行 | 获准字段由快照常量化，动态 load/store、参数和对象身份保持正确 |
| PGO 开/关、不同 quota | 观察与真实 dispatch 分开统计，Gen/Use 身份一致 |
| 编译失败、队列满、资源耗尽 | 有界退避，保持正确通用执行，不阻塞 TTI |
| 多小时变化、未退出调用及 NO_RECLAIM | 预算受控，过期资源不提前释放，耗尽行为符合合同 |

主机模型验证状态机、竞态及窗口边界；真实 runtime 验证快照读取/常量化/队列/PGO/缓存失效；上板验证内存可见性、通用路径结果、最坏检测/关闭时间、完整调用时限和开销。模型测试不能替代真实 500 us 调度与跨核硬截止测量。

性能验收分别记录每 TTI 监测成本、稳定态每次 entry 额外成本、稳定等待时间、排队/编译/发布时间、代码与快照占用，以及完整配置周期内相对通用执行的收益。总监测工作须在 500 us 的系统预算内完成；具体百分比及字段/实例上限由产品给出，本文不承诺未测量的 cycles。

## 14. 落地阶段与待确认事项

1. 业务合同：确定 W、D、截止含义、字段域、revision/值模式及安全读取协议；未确认前不得启用可变字段冻结。
2. 观察与准入：实现有界 TTI 驱动、完整窗口、一致快照及状态诊断；仅验证通用执行下的准入行为。
3. 动态特化闭环：将快照接到编译读取，贯通代际/token、所有快路径失效及有序发布；覆盖失败与资源上限。
4. PGO 与其他功能：验证 T1/T2 及生命周期组合；reuse/小表/phase 仅在各自接口存在时独立集成。
5. 上板与长跑：证明选定的 5 TTI 合同及系统开销，验证长期资源行为后再开放产品 opt-in。

当前未决项为业务合同第 3 节、稳定窗口默认值、配置获取/发布协议、入口失效实现及目标平台预算。本规格提供实现约束与验收标准；业务签字和实现验收分别记录，不能把规格 PR 合并等同于功能已交付。
